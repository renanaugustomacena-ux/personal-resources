## Panoramica

CSS3 (Cascading Style Sheets Level 3) rappresenta l'evoluzione fondamentale del linguaggio di stile utilizzato per definire la presentazione visiva dei documenti HTML. A differenza delle versioni precedenti, CSS3 non costituisce una specifica monolitica, bensì un insieme modulare di specifiche indipendenti, ciascuna delle quali affronta un aspetto specifico della stilizzazione. Tra i moduli principali troviamo Selectors, Box Model, Backgrounds and Borders, Text Effects, Transforms, Transitions, Animations, Flexbox, Grid Layout, Custom Properties e molti altri.

L'approccio modulare ha consentito ai browser di implementare le funzionalita in modo progressivo, accelerando notevolmente l'adozione delle nuove caratteristiche. Oggi CSS3 e il linguaggio imprescindibile per la costruzione di interfacce web moderne, responsive e accessibili. Dalla gestione dei layout complessi con flexbox e grid, alla creazione di animazioni fluide, fino al supporto per temi dinamici tramite custom properties, CSS3 offre agli sviluppatori un arsenale completo per tradurre qualsiasi progetto grafico in codice performante.

La padronanza di CSS3 richiede la comprensione non solo delle singole proprieta, ma anche dei meccanismi fondamentali che governano il linguaggio: la cascata, la specificita, l'ereditarieta e il box model. Questi concetti costituiscono le fondamenta su cui costruire qualsiasi layout, indipendentemente dalla complessita del progetto.

Negli ultimi anni, CSS3 ha conosciuto un'accelerazione senza precedenti nell'introduzione di nuove funzionalita. Le container queries permettono ai componenti di adattarsi al contesto in cui sono inseriti, le cascade layers offrono un controllo granulare sulla priorita degli stili, la pseudo-classe `:has()` consente finalmente la selezione condizionale del genitore, e gli spazi colore moderni come OKLCH aprono nuove possibilita per la gestione cromatica. La combinazione di queste funzionalita con i preprocessori come Sass e i framework come Tailwind CSS e Bootstrap crea un ecosistema potente e versatile, capace di soddisfare le esigenze dei progetti piu ambiziosi.

## Fondamenti e Cascata

### Selettori

I selettori rappresentano il meccanismo attraverso cui CSS identifica gli elementi HTML a cui applicare le regole di stile. CSS3 ha introdotto un numero significativo di nuovi selettori, ampliando enormemente le possibilita di targeting degli elementi.

**Selettori di base:**

```css
/* Selettore di elemento */
p { color: #333; }

/* Selettore di classe */
.container { max-width: 1200px; }

/* Selettore di ID */
#header { position: sticky; top: 0; }

/* Selettore universale */
* { box-sizing: border-box; }
```

**Selettori di attributo:**

```css
/* Elemento con attributo presente */
[data-theme] { transition: background-color 0.3s; }

/* Valore esatto */
[type="email"] { border-color: blue; }

/* Valore che inizia con */
[href^="https"] { color: green; }

/* Valore che termina con */
[href$=".pdf"] { background-image: url(pdf-icon.svg); }

/* Valore che contiene */
[class*="btn"] { cursor: pointer; }
```

**Combinatori:**

I combinatori definiscono la relazione strutturale tra gli elementi selezionati.

```css
/* Discendente (qualsiasi livello di profondita) */
article p { line-height: 1.8; }

/* Figlio diretto (>) */
nav > ul { list-style: none; }

/* Fratello adiacente (+) */
h2 + p { margin-top: 0; font-size: 1.1em; }

/* Fratello generale (~) */
h2 ~ p { color: #555; }
```

Il combinatore discendente seleziona tutti gli elementi che si trovano all'interno di un antenato, indipendentemente dal livello di annidamento. Il combinatore figlio diretto e piu restrittivo e seleziona solo gli elementi che sono figli immediati. Il fratello adiacente seleziona l'elemento immediatamente successivo che condivide lo stesso genitore, mentre il fratello generale seleziona tutti i fratelli successivi.

### Pseudo-classi

Le pseudo-classi permettono di selezionare elementi in base al loro stato, posizione o relazione con altri elementi, senza necessita di aggiungere classi nel markup HTML.

```css
/* Stati interattivi */
a:hover { text-decoration: underline; }
input:focus { outline: 2px solid #007bff; outline-offset: 2px; }
button:active { transform: scale(0.98); }

/* Pseudo-classi strutturali */
li:nth-child(odd) { background-color: #f8f9fa; }
li:nth-child(3n+1) { font-weight: bold; }
p:first-of-type { font-size: 1.2em; }
tr:last-child { border-bottom: none; }

/* Pseudo-classi di negazione e selezione */
input:not([type="submit"]) { border: 1px solid #ccc; }
:is(h1, h2, h3) { font-family: 'Georgia', serif; }
:where(article, section) p { line-height: 1.7; }

/* :has — il selettore genitore */
article:has(img) { display: grid; grid-template-columns: 1fr 2fr; }
form:has(input:invalid) { border: 2px solid red; }
```

La pseudo-classe `:is()` accetta una lista di selettori e seleziona qualsiasi elemento che corrisponda ad almeno uno di essi, contribuendo alla specificita con il selettore piu specifico della lista. La pseudo-classe `:where()` funziona in modo identico, ma con specificita pari a zero, rendendola ideale per stili di base facilmente sovrascrivibili. La pseudo-classe `:has()` rappresenta una delle aggiunte piu rivoluzionarie, permettendo finalmente di selezionare un elemento genitore in base al contenuto dei suoi discendenti.

### Pseudo-elementi

Gli pseudo-elementi consentono di creare e stilizzare parti virtuali di un elemento, generando contenuto aggiuntivo o selezionando porzioni specifiche del testo.

```css
/* Contenuto generato */
.quote::before {
  content: "\201C"; /* virgoletta aperta */
  font-size: 3em;
  color: #ccc;
}

.external-link::after {
  content: " \2197"; /* freccia esterna */
  font-size: 0.8em;
}

/* Selezione del testo */
p::first-line {
  font-variant: small-caps;
  font-weight: 600;
}

p::first-letter {
  font-size: 3em;
  float: left;
  line-height: 1;
  margin-right: 0.1em;
}

/* Personalizzazione dei marcatori di lista */
li::marker {
  color: #007bff;
  font-weight: bold;
}

/* Stile della selezione dell'utente */
::selection {
  background-color: #007bff;
  color: white;
}
```

E fondamentale ricordare che `::before` e `::after` richiedono la proprieta `content` per essere visualizzati. Anche se il contenuto e vuoto (`content: ""`), la dichiarazione e obbligatoria.

### Calcolo della Specificita

La specificita determina quale regola CSS prevale quando piu regole si applicano allo stesso elemento. Si calcola come una terna di valori (A, B, C):

- **A** — Numero di selettori ID
- **B** — Numero di selettori di classe, attributo e pseudo-classi
- **C** — Numero di selettori di elemento e pseudo-elementi

```css
/* Specificita: (0, 0, 1) */
p { color: black; }

/* Specificita: (0, 1, 0) */
.text { color: blue; }

/* Specificita: (1, 0, 0) */
#main { color: red; }

/* Specificita: (0, 1, 1) */
p.text { color: green; }

/* Specificita: (1, 1, 1) */
#main p.text { color: purple; }
```

La specificita si confronta da sinistra a destra: un singolo ID supera qualsiasi numero di classi, e una singola classe supera qualsiasi numero di selettori di elemento. Gli stili inline hanno una specificita superiore a qualsiasi selettore, e la dichiarazione `!important` sovrascrive tutto (da usare con estrema parsimonia).

### Cascade Layers (@layer)

I cascade layers, introdotti con `@layer`, offrono un controllo esplicito sull'ordine di priorita dei fogli di stile, indipendentemente dalla specificita.

```css
/* Dichiarazione dell'ordine dei layer */
@layer reset, base, components, utilities;

@layer reset {
  * { margin: 0; padding: 0; box-sizing: border-box; }
}

@layer base {
  body { font-family: system-ui, sans-serif; line-height: 1.6; }
  a { color: #007bff; }
}

@layer components {
  .card {
    border: 1px solid #e0e0e0;
    border-radius: 8px;
    padding: 1.5rem;
  }
  .btn {
    padding: 0.5rem 1rem;
    border-radius: 4px;
    cursor: pointer;
  }
}

@layer utilities {
  .text-center { text-align: center; }
  .mt-1 { margin-top: 0.5rem; }
}
```

I layer dichiarati per primi hanno la priorita piu bassa. Gli stili al di fuori di qualsiasi layer hanno la priorita massima. Questo meccanismo risolve elegantemente i conflitti tra librerie di terze parti e stili personalizzati.

### Ereditarieta

Non tutte le proprieta CSS vengono ereditate automaticamente dai figli. Le proprieta tipografiche (`color`, `font-family`, `line-height`) vengono ereditate, mentre le proprieta di layout (`margin`, `padding`, `border`) no.

```css
.parent {
  color: inherit;      /* Eredita il valore dal genitore */
  margin: initial;     /* Ripristina il valore predefinito del browser */
  padding: unset;      /* inherit se ereditabile, altrimenti initial */
  border: revert;      /* Ripristina il valore del foglio di stile dell'user agent */
}
```

La parola chiave `revert` e particolarmente utile quando si lavora con i cascade layers, poiche ripristina il valore al layer precedente.

### Box Model

Il box model definisce come viene calcolata la dimensione di ogni elemento. Ogni elemento e composto da contenuto, padding, bordo e margine.

```css
/* content-box (default): width e height si riferiscono solo al contenuto */
.content-box {
  box-sizing: content-box;
  width: 300px;      /* Larghezza totale = 300 + padding + border */
  padding: 20px;
  border: 2px solid;
  /* Larghezza visiva effettiva = 344px */
}

/* border-box: width e height includono padding e bordo */
.border-box {
  box-sizing: border-box;
  width: 300px;      /* Larghezza totale = 300px (il contenuto si adatta) */
  padding: 20px;
  border: 2px solid;
  /* Larghezza visiva effettiva = 300px */
}

/* Reset universale consigliato */
*, *::before, *::after {
  box-sizing: border-box;
}
```

L'uso universale di `border-box` e considerato una best practice consolidata, poiche rende il calcolo delle dimensioni molto piu intuitivo e prevedibile.

## Layout Moderno

### Flexbox

Flexbox (Flexible Box Layout) e un modello di layout unidimensionale progettato per distribuire lo spazio tra gli elementi di un container e allinearli lungo un singolo asse, sia orizzontale che verticale.

**Proprieta del container:**

```css
.flex-container {
  display: flex;                    /* Attiva il contesto flex */
  flex-direction: row;              /* row | row-reverse | column | column-reverse */
  flex-wrap: wrap;                  /* nowrap | wrap | wrap-reverse */
  justify-content: space-between;   /* flex-start | flex-end | center | space-between | space-around | space-evenly */
  align-items: center;             /* flex-start | flex-end | center | stretch | baseline */
  align-content: flex-start;       /* Allineamento delle righe quando flex-wrap e attivo */
  gap: 1rem;                       /* Spazio tra gli elementi (row-gap e column-gap) */
}
```

La proprieta `flex-direction` definisce l'asse principale: `row` per orizzontale (default), `column` per verticale. La proprieta `justify-content` distribuisce lo spazio lungo l'asse principale, mentre `align-items` allinea gli elementi lungo l'asse trasversale. La proprieta `gap` e la modalita moderna per aggiungere spaziatura tra gli elementi, sostituendo i vecchi hack basati sui margini.

**Proprieta degli elementi:**

```css
.flex-item {
  flex-grow: 1;       /* Proporzione di spazio aggiuntivo da assorbire */
  flex-shrink: 0;     /* Proporzione di riduzione quando lo spazio scarseggia */
  flex-basis: 250px;  /* Dimensione iniziale prima della distribuzione dello spazio */
  flex: 1 0 250px;    /* Shorthand: grow shrink basis */
  order: 2;           /* Ordine visivo dell'elemento (default: 0) */
  align-self: flex-end; /* Sovrascrive align-items per questo elemento */
}
```

Lo shorthand `flex` e la forma preferita. I valori comuni includono `flex: 1` (l'elemento cresce per riempire lo spazio), `flex: none` (l'elemento mantiene la dimensione naturale) e `flex: 0 1 auto` (il valore predefinito).

**Pattern comuni con Flexbox:**

```css
/* Centratura perfetta */
.center-container {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}

/* Navbar responsive */
.navbar {
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 1rem 2rem;
}

.navbar__links {
  display: flex;
  gap: 1.5rem;
  list-style: none;
}

/* Card layout con altezza uniforme */
.card-grid {
  display: flex;
  flex-wrap: wrap;
  gap: 1.5rem;
}

.card {
  flex: 1 1 300px;
  display: flex;
  flex-direction: column;
}

.card__content { flex: 1; }
.card__footer { margin-top: auto; }

/* Holy Grail Layout */
.holy-grail {
  display: flex;
  flex-direction: column;
  min-height: 100vh;
}

.holy-grail__body {
  display: flex;
  flex: 1;
}

.holy-grail__main { flex: 1; }
.holy-grail__sidebar { flex: 0 0 250px; }
```

### Grid

CSS Grid Layout e un sistema di layout bidimensionale che permette di controllare simultaneamente righe e colonne, ideale per layout complessi e strutturati.

**Proprieta del container:**

```css
.grid-container {
  display: grid;
  grid-template-columns: 1fr 2fr 1fr;         /* Tre colonne con unita frazionarie */
  grid-template-rows: auto 1fr auto;           /* Tre righe */
  grid-template-areas:
    "header header header"
    "sidebar main aside"
    "footer footer footer";
  gap: 1.5rem;                                  /* Spazio tra celle */
  grid-auto-flow: row;                          /* row | column | dense */
}
```

**Proprieta degli elementi:**

```css
.grid-item {
  grid-column: 1 / 3;      /* Dalla linea 1 alla linea 3 (occupa 2 colonne) */
  grid-row: 2 / span 2;    /* Dalla riga 2, si estende per 2 righe */
  grid-area: header;        /* Posizionamento tramite area nominata */
  place-self: center end;   /* Shorthand per align-self e justify-self */
}
```

**Unita fr, repeat(), minmax(), auto-fit e auto-fill:**

L'unita `fr` (fraction) rappresenta una frazione dello spazio disponibile nel container grid. E la chiave per creare layout flessibili senza ricorrere a percentuali.

```css
/* repeat() per evitare ripetizioni */
.grid { grid-template-columns: repeat(3, 1fr); }

/* minmax() per dimensioni minime e massime */
.grid { grid-template-columns: repeat(3, minmax(200px, 1fr)); }

/* auto-fit: le colonne si espandono per riempire lo spazio */
.responsive-grid {
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
}

/* auto-fill: mantiene le colonne vuote per preservare la struttura */
.grid-with-gaps {
  grid-template-columns: repeat(auto-fill, minmax(250px, 1fr));
}
```

La differenza tra `auto-fit` e `auto-fill` diventa visibile quando ci sono pochi elementi: `auto-fit` collassa le tracce vuote e espande quelle occupate, mentre `auto-fill` mantiene le tracce vuote.

**Aree nominate:**

```css
.dashboard {
  display: grid;
  grid-template-areas:
    "nav    nav    nav"
    "sidebar main  main"
    "sidebar footer footer";
  grid-template-columns: 250px 1fr 1fr;
  grid-template-rows: auto 1fr auto;
  min-height: 100vh;
}

.nav     { grid-area: nav; }
.sidebar { grid-area: sidebar; }
.main    { grid-area: main; }
.footer  { grid-area: footer; }
```

Le aree nominate rendono il codice estremamente leggibile e facilitano la modifica del layout tramite media queries, semplicemente ridefinendo `grid-template-areas`.

**Subgrid:**

Subgrid permette a un elemento figlio del grid di ereditare le tracce (colonne o righe) del grid genitore, mantenendo l'allineamento tra livelli annidati.

```css
.grid-parent {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 1rem;
}

.grid-child {
  grid-column: span 4;
  display: grid;
  grid-template-columns: subgrid; /* Eredita le colonne del genitore */
  gap: 1rem;
}
```

Subgrid e particolarmente utile per le card in un grid, dove si desidera che titolo, contenuto e footer di tutte le card si allineino orizzontalmente, indipendentemente dalla lunghezza del contenuto.

**Pattern comuni con Grid:**

```css
/* Griglia responsive senza media queries */
.auto-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 300px), 1fr));
  gap: 1.5rem;
}

/* Dashboard layout */
.dashboard-grid {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  grid-auto-rows: minmax(150px, auto);
  gap: 1rem;
}

.widget-large { grid-column: span 2; grid-row: span 2; }
.widget-wide  { grid-column: span 2; }
.widget-tall  { grid-row: span 2; }

/* Magazine layout */
.magazine {
  display: grid;
  grid-template-columns: repeat(6, 1fr);
  grid-auto-rows: 200px;
  gap: 1rem;
}

.featured {
  grid-column: span 4;
  grid-row: span 2;
}

.secondary { grid-column: span 2; }
```

### Container Queries

Le container queries rappresentano un cambio di paradigma: mentre le media queries rispondono alle dimensioni del viewport, le container queries rispondono alle dimensioni del container genitore dell'elemento.

```css
/* Definizione del container */
.card-container {
  container-type: inline-size;   /* Monitora la dimensione inline (larghezza) */
  container-name: card-wrapper;  /* Nome opzionale del container */
}

/* Shorthand */
.card-container {
  container: card-wrapper / inline-size;
}

/* Query basata sulle dimensioni del container */
@container card-wrapper (min-width: 400px) {
  .card {
    display: grid;
    grid-template-columns: 200px 1fr;
    gap: 1rem;
  }
}

@container card-wrapper (min-width: 700px) {
  .card {
    grid-template-columns: 300px 1fr;
  }
  .card__title { font-size: 1.5rem; }
}
```

I casi d'uso principali includono: componenti riutilizzabili che si adattano al contesto in cui vengono inseriti, sidebar che modificano il layout delle card in base allo spazio disponibile, e sistemi di design dove i componenti devono essere completamente indipendenti dal layout della pagina.

Le container queries supportano anche unita relative al container: `cqw` (1% della larghezza del container), `cqh` (1% dell'altezza), `cqi` (1% della dimensione inline), `cqb` (1% della dimensione block), `cqmin` e `cqmax`. Queste unita permettono di creare tipografia e spaziature fluide relative al container, non al viewport.

```css
@container (min-width: 300px) {
  .card__title {
    font-size: clamp(1rem, 4cqi, 1.5rem);
    padding: 2cqi;
  }
}
```

## Responsive Design

### Media Queries

Le media queries permettono di applicare stili CSS condizionali in base alle caratteristiche del dispositivo o del viewport.

```css
/* Sintassi base */
@media screen and (min-width: 768px) {
  .container { max-width: 720px; }
}

/* Sintassi moderna con range */
@media (width >= 768px) {
  .container { max-width: 720px; }
}

/* Combinazione di condizioni */
@media (width >= 768px) and (width < 1024px) {
  .container { max-width: 960px; }
}

/* Media query per preferenze utente */
@media (prefers-color-scheme: dark) {
  :root { --bg: #1a1a2e; --text: #e0e0e0; }
}

@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.001ms !important; transition-duration: 0.001ms !important; }
}

@media (hover: none) {
  .tooltip { display: none; } /* Dispositivi touch */
}
```

### Strategia dei Breakpoints

La scelta dei breakpoints deve essere guidata dal contenuto, non dai dispositivi specifici. Tuttavia, esistono breakpoints comunemente adottati che coprono la maggior parte degli scenari:

```css
/* Breakpoints comuni — approccio mobile-first */
/* Smartphone:     < 576px  (stili di base, nessuna media query) */
/* Tablet:         >= 576px */
/* Tablet landscape: >= 768px */
/* Desktop:        >= 1024px */
/* Desktop large:  >= 1280px */
/* Widescreen:     >= 1536px */

/* Esempio mobile-first */
.grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}

@media (width >= 576px) {
  .grid { grid-template-columns: repeat(2, 1fr); }
}

@media (width >= 1024px) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}

@media (width >= 1280px) {
  .grid { grid-template-columns: repeat(4, 1fr); }
}
```

### Approccio Mobile-First

L'approccio mobile-first consiste nello scrivere prima gli stili per i dispositivi piu piccoli e successivamente aggiungere complessita attraverso media queries con `min-width`. Questo approccio garantisce che la versione mobile funzioni anche su browser che non supportano le media queries e incoraggia una gerarchia dei contenuti piu pulita. La logica sottostante e semplice: e piu facile aggiungere complessita (colonne aggiuntive, decorazioni, spaziature maggiori) man mano che lo spazio disponibile cresce, piuttosto che rimuovere elementi e semplificare un layout complesso per adattarlo a schermi piccoli. Inoltre, i dispositivi mobili tendono ad avere hardware meno potente e connessioni piu lente, quindi caricare prima il CSS essenziale e aggiungere progressivamente gli stili per schermi piu grandi offre un vantaggio significativo in termini di performance.

### Unita del Viewport

Le unita del viewport sono proporzionali alle dimensioni della finestra del browser.

```css
.hero {
  /* Unita classiche */
  width: 100vw;     /* 100% della larghezza del viewport */
  height: 100vh;    /* 100% dell'altezza del viewport */
  font-size: 5vmin; /* 5% della dimensione piu piccola tra larghezza e altezza */
  padding: 2vmax;   /* 2% della dimensione piu grande */
}

.section {
  /* Nuove unita viewport per dispositivi mobili */
  min-height: 100dvh;  /* Dynamic viewport height: si adatta alla barra degli indirizzi */
  /* 100svh: Small viewport height — altezza minima (barra visibile) */
  /* 100lvh: Large viewport height — altezza massima (barra nascosta) */
}
```

Le nuove unita `dvh`, `svh` e `lvh` risolvono il problema storico dell'unita `vh` sui dispositivi mobili, dove la barra degli indirizzi del browser modifica l'altezza effettiva del viewport. L'unita `dvh` si aggiorna dinamicamente quando la barra appare o scompare, rendendola la scelta ideale per sezioni a tutta altezza su mobile.

### Tipografia Fluida con clamp()

La funzione `clamp()` permette di definire un valore minimo, un valore preferito e un valore massimo, creando una tipografia che si adatta fluidamente alle dimensioni del viewport.

```css
.heading {
  /* clamp(minimo, preferito, massimo) */
  font-size: clamp(1.5rem, 4vw + 0.5rem, 3.5rem);
}

.paragraph {
  font-size: clamp(1rem, 1.5vw + 0.5rem, 1.25rem);
  line-height: clamp(1.5, 1.2 + 0.5vw, 1.8);
}

.container {
  width: clamp(320px, 90vw, 1200px);
  padding: clamp(1rem, 3vw, 3rem);
}
```

Questa tecnica elimina la necessita di scrivere multiple media queries per le dimensioni del testo, garantendo una transizione fluida e continua. La formula per calcolare il valore preferito di `clamp()` segue questo schema: partendo dal valore minimo desiderato al breakpoint inferiore e dal valore massimo desiderato al breakpoint superiore, si calcola la pendenza della crescita. Numerosi strumenti online facilitano questo calcolo, ma la comprensione del principio sottostante e fondamentale per personalizzare i valori in modo consapevole.

### Design Tokens

I design tokens rappresentano le decisioni di design in formato astratto, creando un'unica fonte di verita per l'intero sistema di design.

```css
  --button-radius: var(--radius-md);
  --button-padding: var(--spacing-sm) var(--spacing-md);
```

Questa stratificazione a tre livelli (primitivi, semantici, componente) garantisce massima flessibilita e manutenibilita. I token primitivi definiscono la palette grezza, i token semantici assegnano significato ai colori nel contesto dell'interfaccia, e i token per componente isolano le scelte stilistiche di ogni singolo componente. Se il team di design decide di cambiare il colore primario, basta modificare un singolo token semantico e l'intero sistema si aggiorna coerentemente.

### Architetture CSS

**BEM (Block Element Modifier):**

```css
/* Block */
.card { }

/* Element (doppio underscore) */
.card__title { }
.card__image { }
.card__body { }

/* Modifier (doppio trattino) */
.card--featured { }
.card--compact { }
.card__title--large { }
```

BEM e la convenzione di nomenclatura piu diffusa. La sua struttura chiara riduce i conflitti di nome e rende il codice autoesplicativo.

**OOCSS (Object-Oriented CSS):** Separa la struttura dalla presentazione e il container dal contenuto. Gli oggetti CSS sono pattern visivi riutilizzabili, come il media object.

**SMACSS (Scalable and Modular Architecture for CSS):** Organizza gli stili in cinque categorie: Base, Layout, Module, State, Theme. Ogni categoria ha regole specifiche di nomenclatura e applicazione.

**ITCSS (Inverted Triangle CSS):** Organizza gli stili dal generico allo specifico, a forma di triangolo invertito: Settings, Tools, Generic, Elements, Objects, Components, Utilities. Ogni strato ha una specificita crescente.

**Cube CSS:** Composition, Utility, Block, Exception. Si concentra sulla composizione globale e utilizza le utilities per le proprieta visive di basso livello, i blocchi per i componenti e le eccezioni per le variazioni di stato. Cube CSS e particolarmente interessante perche abbraccia la cascata CSS anziche combatterla, a differenza di molte altre metodologie che cercano di isolare completamente ogni componente. Questo approccio risulta piu naturale e sfrutta appieno la potenza del linguaggio.

La scelta della metodologia dipende dalla dimensione del progetto, dal team e dalle preferenze personali. Per progetti piccoli, BEM da solo puo essere sufficiente. Per progetti di medie e grandi dimensioni, la combinazione di BEM con ITCSS o l'adozione di Cube CSS offre una struttura solida e scalabile.

## Animazioni e Transizioni

### Transizioni

Le transizioni permettono di animare il passaggio tra due stati di un elemento in modo fluido.

```css
.button {
  background-color: var(--color-primary);
  color: white;
  padding: 0.75rem 1.5rem;
  border-radius: var(--radius-md);

  /* Sintassi per singola proprieta */
  transition-property: background-color, transform, box-shadow;
  transition-duration: 0.3s;
  transition-timing-function: ease-in-out;
  transition-delay: 0s;

  /* Shorthand */
  transition: background-color 0.3s ease-in-out,
              transform 0.2s ease-out,
              box-shadow 0.3s ease;
}

.button:hover {
  background-color: var(--color-primary-dark);
  transform: translateY(-2px);
  box-shadow: var(--shadow-md);
}

.button:active {
  transform: translateY(0);
}
```

Le funzioni di timing predefinite includono: `ease` (default, accelera poi decelera), `linear` (velocita costante), `ease-in` (partenza lenta), `ease-out` (fine lenta), `ease-in-out` (partenza e fine lente). Per un controllo piu preciso, si utilizza `cubic-bezier(x1, y1, x2, y2)`. Una best practice consolidata e usare `ease-out` per le animazioni di ingresso (l'elemento arriva e decelera dolcemente) e `ease-in` per le animazioni di uscita (l'elemento accelera gradualmente e scompare). Per le transizioni hover e le interazioni utente, `ease-in-out` offre un risultato naturale e piacevole. La funzione `steps()` permette di creare animazioni a scatti, utile per sprite sheet e contatori.

### Keyframes e Animazioni

Le animazioni CSS permettono transizioni complesse tra piu stati, con controllo su iterazione, direzione e stato finale.

```css
/* Definizione dell'animazione */
@keyframes fadeInUp {
  from {
    opacity: 0;
    transform: translateY(30px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

@keyframes pulse {
  0% { transform: scale(1); }
  50% { transform: scale(1.05); }
  100% { transform: scale(1); }
}

@keyframes rotate {
  from { transform: rotate(0deg); }
  to { transform: rotate(360deg); }
}

/* Applicazione dell'animazione */
.card {
  animation-name: fadeInUp;
  animation-duration: 0.6s;
  animation-timing-function: ease-out;
  animation-delay: 0.2s;
  animation-iteration-count: 1;
  animation-direction: normal;       /* normal | reverse | alternate | alternate-reverse */
  animation-fill-mode: both;         /* none | forwards | backwards | both */
  animation-play-state: running;     /* running | paused */

  /* Shorthand */
  animation: fadeInUp 0.6s ease-out 0.2s 1 normal both;
}

.spinner {
  animation: rotate 1s linear infinite;
}

.notification {
  animation: pulse 2s ease-in-out infinite;
}
```

La proprieta `animation-fill-mode` e cruciale: `forwards` mantiene lo stile dell'ultimo keyframe al termine dell'animazione, `backwards` applica lo stile del primo keyframe durante il delay, `both` applica entrambi i comportamenti.

### Transform

Le trasformazioni CSS modificano la geometria visiva di un elemento senza influenzare il flusso del documento.

```css
.element {
  /* Trasformazioni singole */
  transform: translateX(50px);
  transform: translateY(-20px);
  transform: translate(50px, -20px);   /* X e Y combinati */
  transform: rotate(45deg);
  transform: scale(1.5);
  transform: scale(1.5, 0.8);         /* scaleX e scaleY */
  transform: skew(10deg, 5deg);

  /* Trasformazioni combinate (l'ordine conta) */
  transform: translate(-50%, -50%) rotate(45deg) scale(1.2);

  /* Punto di origine della trasformazione */
  transform-origin: center center;     /* Default */
  transform-origin: top left;
  transform-origin: 50% 100%;

  /* Trasformazioni 3D */
  transform: perspective(1000px) rotateY(30deg);
  transform: translate3d(10px, 20px, 30px);
}
```

L'ordine delle trasformazioni nella dichiarazione `transform` e significativo: le trasformazioni vengono applicate da destra a sinistra. Pertanto `translate() rotate()` produce un risultato diverso da `rotate() translate()`.

### will-change e Performance

La proprieta `will-change` informa il browser che un elemento subira una modifica specifica, permettendo ottimizzazioni preventive.

```css
/* Utilizzo corretto: applicare solo quando necessario */
.card:hover {
  will-change: transform;
}

.animated-element {
  will-change: transform, opacity;
}

/* NON applicare will-change a troppi elementi contemporaneamente */
/* NON usare will-change: all — e controproducente */
```

E importante usare `will-change` con parsimonia: ogni elemento con `will-change` consuma risorse GPU aggiuntive. L'ideale e aggiungerlo tramite JavaScript poco prima dell'animazione e rimuoverlo al termine.

### Riduzione del Movimento

L'accessibilita e fondamentale. La media query `prefers-reduced-motion` permette di rispettare le preferenze degli utenti che hanno attivato la riduzione delle animazioni nelle impostazioni del sistema operativo.

```css
/* Approccio consigliato: animazioni attive solo se non c'e preferenza di riduzione */
@media (prefers-reduced-motion: no-preference) {
  .animate-on-scroll {
    animation: fadeInUp 0.6s ease-out both;
  }
}

/* Alternativa: rimuovere le animazioni quando richiesto */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.001ms !important;
    scroll-behavior: auto !important;
  }
}
```

### View Transitions API

La View Transitions API rappresenta il futuro delle animazioni tra pagine e stati dell'applicazione. Permette di creare transizioni fluide tra viste diverse, sia nelle Single Page Application (SPA) che nelle Multi Page Application (MPA).

```css
/* Definizione della transizione */
::view-transition-old(root) {
  animation: fade-out 0.3s ease-out;
}

::view-transition-new(root) {
  animation: fade-in 0.3s ease-in;
}

/* Assegnazione di nomi per transizioni specifiche */
.hero-image {
  view-transition-name: hero;
}

::view-transition-old(hero) {
  animation: scale-down 0.4s ease-in-out;
}

::view-transition-new(hero) {
  animation: scale-up 0.4s ease-in-out;
}
```

Questa API, ancora in fase di maturazione, promette di semplificare enormemente le transizioni che tradizionalmente richiedevano librerie JavaScript complesse. La View Transitions API funziona scattando uno "screenshot" dello stato precedente, applicando le modifiche al DOM, e poi animando la transizione tra il vecchio e il nuovo stato. Per le SPA, la transizione viene attivata tramite `document.startViewTransition()` in JavaScript. Per le MPA, e sufficiente aggiungere il meta tag `<meta name="view-transition" content="same-origin">` e le regole CSS corrispondenti. Il supporto dei browser e in rapida espansione, rendendo questa API sempre piu praticabile per i progetti in produzione.

## Tipografia e Colori

### @font-face e font-display

La regola `@font-face` permette di utilizzare font personalizzati, caricandoli da file locali o remoti.

```css
@font-face {
  font-family: 'CustomFont';
  src: url('/fonts/custom-font.woff2') format('woff2'),
       url('/fonts/custom-font.woff') format('woff');
  font-weight: 400;
  font-style: normal;
  font-display: swap;     /* auto | block | swap | fallback | optional */
}
```

La proprieta `font-display` controlla il comportamento durante il caricamento del font: `swap` mostra immediatamente il font di fallback e sostituisce quando il font personalizzato e pronto (scelta consigliata per la maggior parte dei casi), `fallback` offre un breve periodo di invisibilita seguito dal fallback, `optional` lascia al browser la decisione in base alla velocita della connessione.

### Font Variabili

I font variabili racchiudono un intero range di variazioni (peso, larghezza, inclinazione) in un singolo file, riducendo drasticamente il numero di richieste HTTP.

```css
@font-face {
  font-family: 'InterVariable';
  src: url('/fonts/Inter-Variable.woff2') format('woff2-variations');
  font-weight: 100 900;   /* Range supportato */
  font-style: normal;
  font-display: swap;
}

.title {
  font-family: 'InterVariable', sans-serif;
  font-weight: 750;       /* Qualsiasi valore nel range, non solo i multipli di 100 */
  font-variation-settings: 'wght' 750, 'slnt' -10;
}
```

### Formati Colore

CSS3 offre una ricca gamma di formati per esprimere i colori, ciascuno con vantaggi specifici.

```css
.colors {
  /* Esadecimale */
  color: #ff6b35;
  color: #ff6b35cc;         /* Con trasparenza (alpha) */

  /* RGB / RGBA */
  color: rgb(255, 107, 53);
  color: rgb(255 107 53 / 0.8);  /* Sintassi moderna con alpha */

  /* HSL — Tonalita (0-360), Saturazione, Luminosita */
  color: hsl(20, 100%, 60%);
  color: hsl(20 100% 60% / 0.8);

  /* OKLCH — Spazio colore percettivamente uniforme */
  color: oklch(0.7 0.15 50);      /* Luminosita, Crominanza, Tonalita */
  color: oklch(0.7 0.15 50 / 0.8);

  /* color-mix() — Mescolanza di colori */
  color: color-mix(in srgb, #ff0000 50%, #0000ff);
  color: color-mix(in oklch, var(--primary) 70%, black);
}
```

OKLCH sta emergendo come formato preferito per i sistemi di design moderni grazie alla sua uniformita percettiva: modificare la luminosita non altera la tonalita percepita, a differenza di HSL dove una modifica della luminosita puo spostare visivamente la tonalita. Questo rende OKLCH ideale per generare scale di colori coerenti e palette accessibili. La funzione `color-mix()` e estremamente utile per creare varianti di un colore base senza dover calcolare manualmente i valori: si possono generare tinte e ombre mescolando il colore base con bianco o nero in proporzioni variabili, oppure creare colori intermedi tra due colori del brand.

### Filtri e Blend Modes

```css
/* Filtri CSS */
.image-effects {
  filter: blur(5px);
  filter: brightness(1.2);
  filter: contrast(1.5);
  filter: grayscale(100%);
  filter: saturate(2);
  filter: sepia(80%);
  filter: hue-rotate(90deg);
  filter: drop-shadow(4px 4px 8px rgba(0,0,0,0.3));

  /* Filtri combinati */
  filter: brightness(1.1) contrast(1.2) saturate(1.3);
}

/* Blend modes */
.overlay-text {
  mix-blend-mode: multiply;      /* multiply | screen | overlay | darken | lighten ... */
}

.textured-bg {

  background:
    url('texture.png'),
    linear-gradient(#3498db, #2ecc71);

  border: 1px solid rgba(255, 255, 255, 0.2);
  border-radius: 16px;
}
```

Il `backdrop-filter` e la chiave dell'effetto "glassmorphism", estremamente popolare nel design moderno. Applica filtri all'area dietro l'elemento, creando effetti di trasparenza e sfocatura sofisticati. A differenza di `filter`, che agisce sull'elemento stesso e sui suoi contenuti, `backdrop-filter` agisce esclusivamente sullo sfondo visibile attraverso l'elemento. Questo permette di creare pannelli traslucidi, header flottanti con sfocatura e overlay eleganti. Per ottenere il miglior effetto glassmorphism, e consigliabile combinare `backdrop-filter: blur()` con un background semi-trasparente e un bordo sottile bianco semi-trasparente per simulare la rifrazione della luce.

Sass (Syntactically Awesome Style Sheets) e il preprocessore CSS piu diffuso. Estende CSS con funzionalita come variabili, annidamento, mixin, funzioni e moduli.

```scss
// Variabili Sass (compilate staticamente, a differenza delle custom properties CSS)
$primary: #007bff;

.navbar {

```

**Mixin e funzioni:**

```scss
// Mixin con parametri
@mixin respond-to($breakpoint) {
  @if $breakpoint == 'sm' {
    @media (min-width: 576px) { @content; }
  } @else if $breakpoint == 'md' {
    @media (min-width: 768px) { @content; }
  } @else if $breakpoint == 'lg' {
    @media (min-width: 1024px) { @content; }
  }
}

@mixin flex-center {
  display: flex;
  justify-content: center;
  align-items: center;
}

@mixin truncate($lines: 1) {
  @if $lines == 1 {
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
  } @else {
    display: -webkit-box;
    -webkit-line-clamp: $lines;
    -webkit-box-orient: vertical;
    overflow: hidden;
  }
}

// Utilizzo dei mixin
.hero {
  @include flex-center;
  min-height: 100vh;

  @include respond-to('md') {
    padding: 4rem;
  }
}

.card__description {
  @include truncate(3);
}

// Funzioni personalizzate
@function spacing($multiplier) {
  @return $multiplier * 0.25rem;
}

.section {
  padding: spacing(8);    // Produce 2rem
  margin-bottom: spacing(12); // Produce 3rem
}
```

**Sistema modulare con @use e @forward:**

```scss
// _variables.scss
$primary: #007bff;
$secondary: #6c757d;

// _mixins.scss
@use 'variables' as vars;

@mixin button-variant($bg-color) {
  background-color: $bg-color;
  color: white;
  &:hover { background-color: darken($bg-color, 10%); }
}

// _index.scss (barrel file)
@forward 'variables';
@forward 'mixins';

// main.scss
@use 'index' as *;

.btn-primary {
  @include button-variant($primary);
}
```

Il sistema `@use/@forward` ha sostituito il vecchio `@import`, offrendo namespace, caricamento singolo dei moduli e una struttura piu chiara delle dipendenze.

## Best Practices

1. **Adottare `box-sizing: border-box` globalmente.** Il reset universale `*, *::before, *::after { box-sizing: border-box; }` dovrebbe essere la prima regola di ogni progetto. Rende il calcolo delle dimensioni prevedibile e coerente, eliminando la fonte piu comune di errori di layout. Senza questa regola, padding e bordi si aggiungono alla larghezza dichiarata, causando overflow inaspettati e calcoli complessi.

2. **Progettare con l'approccio mobile-first.** Scrivere prima gli stili per i dispositivi mobili e aggiungere complessita progressivamente tramite media queries con `min-width`. Questo approccio garantisce che l'esperienza base funzioni ovunque, migliora le performance sui dispositivi meno potenti (che caricano meno CSS) e costringe a definire una chiara gerarchia dei contenuti. Inoltre, i dispositivi mobili rappresentano oggi la maggioranza del traffico web.

3. **Utilizzare le custom properties per i valori condivisi.** Definire variabili CSS per colori, spaziature, tipografia e altri valori ricorrenti. Le custom properties, a differenza delle variabili dei preprocessori, sono disponibili a runtime e possono essere modificate dinamicamente tramite JavaScript o media queries. Organizzarle in token primitivi, semantici e per componente crea un sistema scalabile e manutenibile.

4. **Preferire flexbox e grid ai metodi di layout obsoleti.** Evitare `float` per il layout (usarlo solo per il wrapping del testo attorno alle immagini), evitare `display: table` e le tecniche basate su `position: absolute` per strutturare la pagina. Flexbox e ideale per distribuzioni unidimensionali (navbar, liste, centramento), mentre Grid eccelle nei layout bidimensionali (pagine intere, dashboard, griglie di contenuto). Entrambi gestiscono nativamente la spaziatura con `gap`.

5. **Rispettare le preferenze dell'utente per l'accessibilita.** Implementare sempre la media query `prefers-reduced-motion` per disabilitare o ridurre le animazioni per gli utenti che lo richiedono. Supportare il dark mode tramite `prefers-color-scheme`. Garantire che gli stati di focus siano sempre visibili e chiari per la navigazione da tastiera. Non utilizzare mai `outline: none` senza fornire un'alternativa visiva equivalente.

6. **Organizzare il CSS con una metodologia coerente.** Adottare una convenzione di nomenclatura come BEM per le classi e una struttura architettonica come ITCSS o Cube CSS per l'organizzazione dei file. La coerenza nella nomenclatura e nella struttura riduce drasticamente il tempo di onboarding per i nuovi membri del team e previene i conflitti di specificita. In un progetto di medie dimensioni, la mancanza di una metodologia porta inevitabilmente al caos.

7. **Minimizzare l'uso di `!important` e di selettori ad alta specificita.** La dichiarazione `!important` deve essere riservata esclusivamente alle classi utility o per sovrascrivere stili di librerie di terze parti che non possono essere modificati altrimenti. Se si sente la necessita di usare `!important` frequentemente, e un segnale che l'architettura CSS necessita di una revisione. I cascade layers (`@layer`) offrono un'alternativa elegante per gestire la priorita degli stili.

8. **Ottimizzare le performance delle animazioni.** Animare preferibilmente solo le proprieta `transform` e `opacity`, poiche sono gestite dal compositing thread del browser e non provocano reflow o repaint. Evitare di animare `width`, `height`, `margin`, `padding`, `top`, `left` e altre proprieta che innescano il ricalcolo del layout. Utilizzare `will-change` con parsimonia e solo sugli elementi che verranno effettivamente animati.

9. **Scrivere CSS mantenibile e documentato.** Aggiungere commenti che spiegano il "perche" delle scelte non ovvie, non il "cosa". Raggruppare le proprieta in modo logico all'interno delle regole (posizionamento, display, box model, tipografia, colori, altro). Eliminare il codice morto regolarmente. Utilizzare strumenti come Stylelint per applicare automaticamente le convenzioni del progetto e individuare errori.

10. **Sfruttare le funzionalita native del CSS moderno prima di ricorrere a JavaScript.** Molte funzionalita che tradizionalmente richiedevano JavaScript sono ora implementabili in puro CSS: smooth scrolling (`scroll-behavior: smooth`), snap points (`scroll-snap-type`), accordion nativi con `<details>`/`<summary>`, dark mode toggle con `:has()` e checkbox, sticky headers, contatori automatici. Il CSS moderno e estremamente potente e ogni riga di JavaScript evitata migliora le performance e la manutenibilita dell'applicazione.

## CSS Moderno Avanzato

Questa sezione approfondisce le funzionalita CSS piu recenti, molte delle quali hanno raggiunto lo status Baseline nel 2024-2025 e sono ora utilizzabili in produzione su tutti i browser moderni. Ogni sottosezione copre la sintassi, i pattern pratici e le implicazioni architetturali delle nuove specifiche.

### CSS Nesting Nativo

Il CSS nesting nativo, standardizzato nel CSS Nesting Module (W3C), porta nel linguaggio la capacita di annidare selettori all'interno di regole genitore, una funzionalita che per anni e stata esclusiva dei preprocessori come Sass e Less. A partire dal 2024 tutti i browser moderni supportano il nesting nativo, eliminando la necessita di strumenti di compilazione per questa specifica funzionalita.

**Sintassi base e operatore `&`:**

L'operatore `&` rappresenta il selettore genitore all'interno di una regola annidata, esattamente come in Sass. Tuttavia, a differenza delle prime implementazioni, la specifica attuale consente di omettere `&` quando il selettore annidato inizia con un simbolo di selettore (`.`, `#`, `[`, `:`, `*`, `+`, `~`, `>`).

```css
.card {
  padding: 1.5rem;
  border-radius: var(--radius-md);
  background: var(--color-surface);

  /* Selettore annidato — equivale a .card .card__title */
  .card__title {
    font-size: 1.25rem;
    font-weight: 600;
    margin-bottom: 0.5rem;
  }

  .card__body {
    line-height: 1.7;
    color: var(--text-secondary);
  }

  /* Pseudo-classi con & */
  &:hover {
    box-shadow: var(--shadow-md);
    transform: translateY(-2px);
  }

  &:focus-within {
    outline: 2px solid var(--color-action);
    outline-offset: 2px;
  }

  /* Modifier con & */
  &.card--featured {
    border-left: 4px solid var(--color-accent);
  }

  /* Media query annidata */
  @media (width >= 768px) {
    display: grid;
    grid-template-columns: 200px 1fr;
    gap: 1rem;
  }
}
```

**Annidamento profondo e limiti pratici:**

Il nesting supporta annidamento a piu livelli, ma e buona prassi limitarsi a 3-4 livelli di profondita per mantenere la leggibilita e la specificita sotto controllo. Ogni livello di annidamento aggiunge specificita al selettore compilato.

```css
.dashboard {
  .sidebar {
    .nav-item {
      color: var(--text-secondary);

      &.active {
        color: var(--color-action);
        font-weight: 600;
      }

      &:hover {
        background: var(--color-surface-hover);
      }
    }
  }
}
```

**Confronto con il nesting di Sass:**

La differenza principale rispetto a Sass riguarda la concatenazione di stringhe: in Sass `&-title` produce `.card-title`, mentre nel nesting nativo CSS `&` rappresenta l'intero selettore genitore e non supporta la concatenazione di stringhe. Per i pattern BEM, si deve continuare a scrivere il selettore completo come figlio annidato (`.card__title`) anziche usare `&__title`. Inoltre, il nesting CSS nativo non supporta le variabili Sass (`$variabile`), le funzioni personalizzate (`@function`), i mixin (`@mixin/@include`) ne il modulo `@use/@forward`. Il nesting nativo e un sottoinsieme focalizzato: organizza la struttura del codice, ma non sostituisce l'intero ecosistema Sass per progetti che richiedono logica di compilazione avanzata.

**Annidamento di regole at-rules:**

Una delle caratteristiche piu potenti del nesting nativo e la possibilita di annidare regole `@media`, `@supports`, `@container` e `@layer` direttamente dentro un selettore, eliminando la duplicazione del contesto.

```css
.hero {
  padding: 2rem;
  font-size: 1rem;

  @media (width >= 768px) {
    padding: 4rem;
    font-size: 1.25rem;
  }

  @media (width >= 1280px) {
    padding: 6rem;
    font-size: 1.5rem;
  }

  @supports (container-type: inline-size) {
    container-type: inline-size;
  }
}
```

### Il Selettore :has() — Pattern Avanzati

La pseudo-classe `:has()` e stata definita il "selettore piu potente mai aggiunto a CSS". Non si tratta semplicemente di un "selettore genitore": e una pseudo-classe relazionale che permette di selezionare qualsiasi elemento in base alla presenza, allo stato o alla struttura dei suoi discendenti, fratelli o successori. Dal 2024 il supporto e universale su tutti i browser moderni, con copertura globale superiore al 95%.

**Validazione dei form senza JavaScript:**

```css
/* Evidenzia il campo-wrapper quando l'input e invalido */
.field:has(input:invalid) {
  border-color: var(--color-danger);
  background: oklch(0.95 0.03 25);
}

/* Mostra il messaggio di errore solo quando l'input e invalido */
.field:has(input:invalid) .field__error {
  display: block;
}

/* Stile del label quando il campo e richiesto */
label:has(+ input:required)::after {
  content: " *";
  color: var(--color-danger);
}

/* Disabilita il pulsante submit se il form ha errori */
form:has(:invalid) button[type="submit"] {
  opacity: 0.5;
  pointer-events: none;
}
```

**Layout condizionali basati sul contenuto:**

`:has()` consente di adattare il layout di un contenitore in base a cio che contiene, un pattern impossibile con qualsiasi altra tecnica CSS.

```css
/* Card con immagine → layout orizzontale */
.card:has(> img) {
  display: grid;
  grid-template-columns: 250px 1fr;
}

/* Card senza immagine → layout verticale semplice */
.card:not(:has(> img)) {
  display: flex;
  flex-direction: column;
}

/* Griglia che si adatta al numero di figli (quantity queries) */
.grid:has(> :nth-child(4)) {
  grid-template-columns: repeat(2, 1fr);
}

.grid:has(> :nth-child(7)) {
  grid-template-columns: repeat(3, 1fr);
}

/* Sezione con video → padding extra per il player */
section:has(video, iframe[src*="youtube"]) {
  padding-block: var(--spacing-xl);
}
```

**Styling contestuale e stato globale:**

```css
/* Dark mode con checkbox nascosto (no JavaScript) */
html:has(#dark-mode-toggle:checked) {
  --bg-primary: #1a1a2e;
  --text-primary: #e0e0e0;
  color-scheme: dark;
}

/* Quando la sidebar e aperta, sposta il contenuto principale */
body:has(.sidebar.open) .main-content {
  margin-inline-start: 280px;
}

/* Stile dell'header quando la pagina ha un hero */
body:has(.hero) header {
  position: absolute;
  background: transparent;
  color: white;
}

/* Stile del fratello successivo basato sul contenuto */
h2:has(+ .subtitle) {
  margin-bottom: 0.25rem;
}
```

**Considerazioni sulle performance:**

Le implementazioni dei browser hanno ottimizzato significativamente `:has()`, ma e consigliabile evitare selettori eccessivamente complessi come `:has(*)` o catene profonde come `.a:has(.b:has(.c:has(.d)))`. Il pattern piu efficiente e `:has()` con selettori figli diretti (`>`) o combinatori adiacenti (`+`), poiche limitano l'ambito di ricerca del browser. Le performance degradano sensibilmente quando `:has()` contiene selettori che attraversano grandi porzioni dell'albero DOM.

### Container Queries Avanzate

Oltre alla sintassi di base trattata nella sezione precedente, le container queries offrono funzionalita avanzate che meritano un approfondimento: le style queries, i container annidati e le strategie architetturali.

**Style queries (query sugli stili):**

Le style queries estendono le container queries permettendo di interrogare il valore delle custom properties del container, non solo le dimensioni. Questa funzionalita abilita pattern di styling condizionale basati su variabili CSS, aprendo scenari completamente nuovi.

```css
.card-container {
  container-type: inline-size;
  container-name: card-wrapper;
}

/* Query basata sul valore di una custom property */
@container card-wrapper style(--theme: dark) {
  .card {
    background: var(--surface-dark);
    color: var(--text-light);
  }
}

@container card-wrapper style(--layout: compact) {
  .card {
    padding: 0.5rem;
    font-size: 0.875rem;
  }
}
```

**Container annidati:**

Quando piu container sono annidati, `@container` seleziona il container piu vicino nell'albero DOM, a meno che non venga specificato un nome esplicito.

```css
.outer {
  container: outer / inline-size;
}

.inner {
  container: inner / inline-size;
}

/* Seleziona il container "outer" esplicitamente */
@container outer (min-width: 800px) {
  .widget {
    grid-template-columns: repeat(3, 1fr);
  }
}

/* Senza nome: seleziona il container piu vicino */
@container (min-width: 400px) {
  .widget__title {
    font-size: 1.25rem;
  }
}
```

**Unita relative al container — approfondimento:**

Le unita container (`cqw`, `cqh`, `cqi`, `cqb`, `cqmin`, `cqmax`) permettono di dimensionare qualsiasi proprieta in relazione al container, non solo la tipografia. Questo apre la strada a spaziature, bordi e dimensioni degli elementi completamente fluid-responsive al contesto.

```css
.responsive-component {
  /* Padding proporzionale alla larghezza del container */
  padding: 3cqi;

  /* Bordo che scala con il container */
  border-width: max(1px, 0.2cqi);

  /* Font size fluido relativo al container */
  font-size: clamp(0.875rem, 2.5cqi, 1.5rem);

  /* Gap che si adatta */
  gap: clamp(0.5rem, 2cqi, 2rem);
}
```

### CSS Subgrid — Approfondimento

Il subgrid, supportato da tutti i browser moderni dal 2024, risolve un problema strutturale dei layout annidati: mantenere l'allineamento tra le tracce del grid genitore e quelle dei grid figli. Senza subgrid, un grid annidato crea le proprie tracce indipendenti, rompendo l'allineamento visivo.

**Allineamento delle card con subgrid:**

Il caso d'uso classico e una griglia di card dove titolo, contenuto e footer devono allinearsi orizzontalmente tra card diverse, indipendentemente dalla lunghezza del contenuto.

```css
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 1.5rem;
}

.card {
  display: grid;
  grid-row: span 3; /* La card occupa 3 righe nel grid genitore */
  grid-template-rows: subgrid; /* Eredita le righe dal genitore */
  gap: 0; /* Gestione gap indipendente */
}

.card__header {
  padding: 1rem;
  font-weight: 600;
}

.card__body {
  padding: 0 1rem;
  /* Il body si espande per riempire lo spazio disponibile */
}

.card__footer {
  padding: 1rem;
  border-top: 1px solid var(--border-color);
  align-self: end;
}
```

**Allineamento dei form con subgrid:**

Subgrid e particolarmente utile per i form dove le label e gli input devono allinearsi su piu righe.

```css
.form-grid {
  display: grid;
  grid-template-columns: max-content 1fr;
  gap: 1rem 2rem;
}

.form-field {
  display: grid;
  grid-column: span 2;
  grid-template-columns: subgrid;
  align-items: center;
}

.form-field label {
  text-align: end;
  font-weight: 500;
}

.form-field input {
  padding: 0.5rem;
  border: 1px solid var(--border-color);
  border-radius: var(--radius-sm);
}
```

**Subgrid bidirezionale:**

E possibile usare subgrid contemporaneamente per righe e colonne, ereditando entrambe le dimensioni dal grid genitore.

```css
.parent-grid {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  grid-template-rows: auto 1fr auto;
  gap: 1rem;
}

.child-element {
  grid-column: span 2;
  grid-row: span 3;
  display: grid;
  grid-template-columns: subgrid;
  grid-template-rows: subgrid;
}
```

### Cascade Layers — Approfondimento

I cascade layers (`@layer`) meritano un'analisi piu approfondita rispetto alla sezione introduttiva, poiche la loro corretta applicazione e fondamentale per gestire progetti complessi con librerie di terze parti.

**Strategia di ordinamento dei layer:**

L'ordine di dichiarazione determina la priorita: l'ultimo layer dichiarato ha la priorita piu alta. Una strategia comune prevede questa gerarchia crescente di priorita.

```css
/* Dichiarazione esplicita dell'ordine — i layer successivi hanno priorita crescente */
@layer reset, vendor, base, layout, components, utilities, overrides;

/* Reset: specificita piu bassa */
@layer reset {
  *, *::before, *::after {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
  }
}

/* Stili di librerie terze parti */
@layer vendor {
  /* @import url("third-party.css") layer(vendor); */
}

/* Tipografia e stili di base */
@layer base {
  body {
    font-family: var(--font-family-base);
    line-height: 1.6;
    color: var(--text-primary);
  }
}

/* Utility con priorita alta */
@layer utilities {
  .sr-only {
    position: absolute;
    width: 1px;
    height: 1px;
    clip: rect(0, 0, 0, 0);
    overflow: hidden;
  }
}
```

**Layer anonimi e `revert-layer`:**

I layer anonimi permettono di isolare blocchi di stili senza nominarli esplicitamente. La keyword `revert-layer` ripristina il valore di una proprieta al layer precedente nella gerarchia.

```css
/* Layer anonimo — utile per stili temporanei o di debug */
@layer {
  .debug { outline: 2px dashed red; }
}

/* revert-layer: ripristina al valore del layer precedente */
@layer components {
  .card {
    padding: 1.5rem;
    background: var(--color-surface);
  }
}

@layer overrides {
  .card.card--reset {
    padding: revert-layer;    /* Torna al valore di "components" */
    background: revert-layer;
  }
}
```

**Importazione di fogli di stile in layer specifici:**

Una delle applicazioni piu pratiche dei layer e l'importazione di CSS di terze parti in un layer a bassa priorita, garantendo che gli stili personalizzati prevalgano sempre senza ricorrere a `!important`.

```css
/* Il CSS della libreria viene caricato nel layer "vendor" */
@import url("bootstrap.min.css") layer(vendor);
@import url("highlight.css") layer(vendor);

/* Gli stili del progetto, fuori da qualsiasi layer o in layer con priorita superiore,
   prevalgono sempre sul vendor — senza bisogno di !important */
@layer components {
  .btn {
    border-radius: var(--radius-md);  /* Sovrascrive Bootstrap */
  }
}
```

**Layer annidati:**

I layer possono essere annidati per creare gerarchie piu granulari, utili nei design system complessi.

```css
@layer components {
  @layer buttons {
    .btn { padding: 0.5rem 1rem; }
  }

  @layer cards {
    .card { padding: 1.5rem; }
  }
}

/* Accesso diretto a un sub-layer */
@layer components.buttons {
  .btn--large { padding: 0.75rem 2rem; }
}
```

### @scope — Scoping di Prossimita

La regola `@scope`, diventata Baseline alla fine del 2024, introduce il concetto di scoping di prossimita nel CSS. A differenza di BEM o CSS Modules, che risolvono i conflitti di nome tramite convenzioni o hash, `@scope` limita l'applicabilita delle regole a un sottoalbero del DOM, con la possibilita di definire un limite inferiore (donut scope).

**Sintassi base:**

```css
@scope (.card) {
  /* Queste regole si applicano SOLO dentro .card */
  h2 { font-size: 1.25rem; }
  p { color: var(--text-secondary); }
  img { border-radius: var(--radius-sm); }
}
```

**Donut scope — esclusione di sottoalberi:**

Il donut scope permette di definire un limite inferiore oltre il quale le regole non si applicano, utile per proteggere componenti annidati dal ricevere stili non desiderati.

```css
/* Stili applicati dentro .article MA NON dentro .comments */
@scope (.article) to (.comments) {
  p {
    font-size: 1.1rem;
    line-height: 1.8;
    max-width: 65ch;
  }

  a {
    color: var(--color-action);
    text-decoration-thickness: 2px;
  }
}

/* I paragrafi dentro .comments NON riceveranno questi stili */
```

**Scoping di prossimita:**

Quando due regole `@scope` si sovrappongono, prevale la regola il cui scope root e piu vicino all'elemento target nell'albero DOM. Questo meccanismo di prossimita risolve elegantemente i conflitti in componenti annidati.

```css
@scope (.light-theme) {
  p { color: #333; }
}

@scope (.dark-theme) {
  p { color: #eee; }
}

/* Se .dark-theme e annidato dentro .light-theme,
   i paragrafi dentro .dark-theme saranno #eee
   perche .dark-theme e il scope root piu vicino */
```

**Confronto con altre strategie di scoping:**

| Strategia | Meccanismo | Vantaggi | Limiti |
|---|---|---|---|
| BEM | Convenzione di nome | Semplice, no tooling | Disciplina manuale, nessun isolamento reale |
| CSS Modules | Hash delle classi a build-time | Isolamento garantito | Richiede bundler, nomi non leggibili in DevTools |
| Shadow DOM | Encapsulation del browser | Isolamento totale | Difficile da stilizzare dall'esterno, piu pesante |
| `@scope` | Regola CSS nativa | Prossimita, donut scope, no tooling | Supporto browser da verificare per target specifici |

### Funzioni Colore Moderne

Lo spazio colore OKLCH e le funzioni `color-mix()` e la sintassi dei colori relativi rappresentano un salto qualitativo nella gestione cromatica CSS, superando i limiti storici di RGB e HSL.

**OKLCH — Approfondimento:**

OKLCH (Oklab Lightness Chroma Hue) e uno spazio colore percettivamente uniforme: una variazione di 0.1 nella luminosita produce la stessa differenza percepita indipendentemente dalla tonalita. In HSL, al contrario, un giallo al 50% di luminosita appare molto piu chiaro di un blu al 50% di luminosita, perche HSL non tiene conto della percezione umana.

```css
:root {
  /* OKLCH: Lightness (0-1), Chroma (0-0.4), Hue (0-360) */
  --primary-50:  oklch(0.97 0.02 250);
  --primary-100: oklch(0.93 0.04 250);
  --primary-200: oklch(0.87 0.08 250);
  --primary-300: oklch(0.78 0.12 250);
  --primary-400: oklch(0.68 0.16 250);
  --primary-500: oklch(0.58 0.19 250);
  --primary-600: oklch(0.50 0.19 250);
  --primary-700: oklch(0.42 0.17 250);
  --primary-800: oklch(0.35 0.14 250);
  --primary-900: oklch(0.28 0.10 250);
}
```

In questa scala, la crominanza e la tonalita rimangono coerenti mentre la luminosita decresce uniformemente, producendo una palette visivamente armoniosa che e impossibile ottenere con HSL.

**`color-mix()` — Ricette pratiche:**

La funzione `color-mix()` mescola due colori in uno spazio colore specificato, con proporzioni personalizzabili. E ideale per generare varianti hover, disabled e overlay senza calcoli manuali.

```css
:root {
  --brand: oklch(0.65 0.2 260);

  /* Tinte (mix con bianco) */
  --brand-light: color-mix(in oklch, var(--brand) 30%, white);
  --brand-lighter: color-mix(in oklch, var(--brand) 15%, white);

  /* Ombre (mix con nero) */
  --brand-dark: color-mix(in oklch, var(--brand) 70%, black);
  --brand-darker: color-mix(in oklch, var(--brand) 50%, black);

  /* Stato hover — scurire del 15% */
  --brand-hover: color-mix(in oklch, var(--brand) 85%, black);

  /* Stato disabled — desaturare */
  --brand-disabled: color-mix(in oklch, var(--brand) 40%, gray);

  /* Overlay trasparente */
  --brand-overlay: color-mix(in srgb, var(--brand) 20%, transparent);
}

.btn-primary {
  background: var(--brand);
  &:hover { background: var(--brand-hover); }
  &:disabled { background: var(--brand-disabled); }
}
```

**Sintassi dei colori relativi:**

La sintassi dei colori relativi permette di derivare un nuovo colore da uno esistente, modificando selettivamente i singoli canali. Questa funzionalita e supportata da tutti i browser moderni e rappresenta il metodo piu flessibile per manipolare i colori in CSS.

```css
:root {
  --base-color: oklch(0.65 0.2 260);

  /* Schiarire aumentando la luminosita */
  --lighter: oklch(from var(--base-color) calc(l + 0.2) c h);

  /* Scurire diminuendo la luminosita */
  --darker: oklch(from var(--base-color) calc(l - 0.15) c h);

  /* Desaturare riducendo la crominanza */
  --muted: oklch(from var(--base-color) l calc(c * 0.5) h);

  /* Colore complementare (ruotare la tonalita di 180 gradi) */
  --complement: oklch(from var(--base-color) l c calc(h + 180));

  /* Colore analogo (ruotare di 30 gradi) */
  --analogous: oklch(from var(--base-color) l c calc(h + 30));

  /* Aggiungere trasparenza */
  --semi-transparent: oklch(from var(--base-color) l c h / 0.5);
}
```

Questa sintassi elimina la necessita di librerie JavaScript per la manipolazione dei colori e permette di costruire interi sistemi di theming con una singola custom property di base.

### @property e Custom Properties Avanzate

La regola `@property` permette di registrare formalmente le custom properties, definendo tipo, valore iniziale e comportamento di ereditarieta. Questa registrazione abilita due funzionalita altrimenti impossibili: l'animazione/transizione delle custom properties e la validazione dei tipi a livello del browser.

**Registrazione con @property:**

```css
/* Registra una custom property con tipo "colore" */
@property --gradient-start {
  syntax: "<color>";
  inherits: false;
  initial-value: oklch(0.6 0.2 260);
}

@property --gradient-end {
  syntax: "<color>";
  inherits: false;
  initial-value: oklch(0.7 0.15 330);
}

/* Ora la custom property puo essere animata con transition */
.gradient-box {
  background: linear-gradient(135deg, var(--gradient-start), var(--gradient-end));
  transition: --gradient-start 0.5s ease, --gradient-end 0.5s ease;
}

.gradient-box:hover {
  --gradient-start: oklch(0.7 0.25 200);
  --gradient-end: oklch(0.8 0.2 150);
}
```

Senza `@property`, le custom properties sono trattate come stringhe opache dal browser e non possono essere interpolate (animate). La registrazione esplicita del tipo (color, length, number, percentage, angle, ecc.) permette al motore CSS di calcolare i valori intermedi durante le transizioni.

**Tipi di sintassi supportati:**

```css
@property --my-length {
  syntax: "<length>";
  inherits: true;
  initial-value: 0px;
}

@property --my-percentage {
  syntax: "<percentage>";
  inherits: false;
  initial-value: 0%;
}

@property --my-number {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}

@property --my-angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

@property --my-integer {
  syntax: "<integer>";
  inherits: false;
  initial-value: 0;
}
```

**Animazione di gradienti e contatori:**

Uno dei pattern piu spettacolari abilitati da `@property` e l'animazione dei gradienti, tradizionalmente impossibile in CSS.

```css
@property --hue-rotation {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

.animated-gradient {
  background: conic-gradient(
    from var(--hue-rotation),
    oklch(0.7 0.2 0),
    oklch(0.7 0.2 120),
    oklch(0.7 0.2 240),
    oklch(0.7 0.2 360)
  );
  animation: rotate-hue 5s linear infinite;
}

@keyframes rotate-hue {
  to { --hue-rotation: 360deg; }
}
```

**Controllo dell'ereditarieta:**

La proprieta `inherits` in `@property` controlla se il valore si propaga ai discendenti. Con `inherits: false`, ogni elemento deve dichiarare esplicitamente il valore, impedendo effetti collaterali da propagazione indesiderata. Con `inherits: true`, il valore si propaga normalmente come le custom properties standard.

### Scroll-Driven Animations

Le scroll-driven animations permettono di legare le animazioni CSS alla posizione di scorrimento anziche al tempo. Questa funzionalita elimina la necessita di librerie JavaScript come GSAP ScrollTrigger o Intersection Observer per molte animazioni legate allo scroll, con un impatto significativo sulle performance poiche il calcolo avviene fuori dal main thread.

**Scroll Timeline:**

Lo scroll timeline lega l'avanzamento dell'animazione alla posizione di scroll di un container scrollabile. L'animazione progredisce dallo 0% al 100% man mano che l'utente scorre dal punto iniziale a quello finale del container.

```css
@keyframes progress-bar {
  from { transform: scaleX(0); }
  to { transform: scaleX(1); }
}

/* Barra di progresso di lettura che si riempie durante lo scroll */
.reading-progress {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  height: 3px;
  background: var(--color-action);
  transform-origin: left;
  animation: progress-bar linear;
  animation-timeline: scroll(root);
}
```

**View Timeline:**

Il view timeline lega l'animazione alla visibilita di un elemento all'interno del suo scroll container. L'animazione inizia quando l'elemento entra nella viewport e progredisce fino a quando non esce.

```css
@keyframes fade-in-up {
  from {
    opacity: 0;
    transform: translateY(50px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

/* Elementi che appaiono progressivamente durante lo scroll */
.reveal-on-scroll {
  animation: fade-in-up linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}
```

**`animation-range` per controllo fine:**

La proprieta `animation-range` definisce in quale porzione della timeline l'animazione e attiva. I valori includono `entry` (l'elemento entra nel viewport), `exit` (l'elemento esce), `contain` (l'elemento e completamente visibile) e `cover` (dalla prima apparizione alla scomparsa completa).

```css
/* Animazione attiva solo durante l'ingresso nel viewport */
.element {
  animation: fade-in linear both;
  animation-timeline: view();
  animation-range: entry 10% entry 90%;
}

/* Parallax: l'elemento si muove piu lentamente dello scroll */
.parallax-bg {
  animation: parallax linear;
  animation-timeline: scroll();
  animation-range: 0% 100%;
}

@keyframes parallax {
  from { transform: translateY(-20%); }
  to { transform: translateY(20%); }
}
```

**Scroll-driven animations e accessibilita:**

E fondamentale rispettare `prefers-reduced-motion` anche per le animazioni scroll-driven. Gli utenti che hanno richiesto la riduzione del movimento non devono subire animazioni legate allo scroll.

```css
@media (prefers-reduced-motion: no-preference) {
  .reveal-on-scroll {
    animation: fade-in-up linear both;
    animation-timeline: view();
    animation-range: entry 0% entry 100%;
  }
}
```

### Anchor Positioning

L'anchor positioning e un meccanismo CSS che permette di posizionare un elemento in relazione a un altro elemento (l'ancora) ovunque nella pagina, senza che i due debbano avere una relazione genitore-figlio nel DOM. Questa funzionalita sostituisce il JavaScript necessario per tooltip, popover, dropdown e menu contestuali. Chrome lo supporta dalla versione 131, e il supporto si sta espandendo rapidamente negli altri browser.

**Sintassi base:**

```css
/* Definizione dell'ancora */
.trigger {
  anchor-name: --my-anchor;
}

/* Posizionamento relativo all'ancora */
.tooltip {
  position: fixed;
  position-anchor: --my-anchor;

  /* Posiziona il bordo superiore del tooltip sotto l'ancora */
  top: anchor(bottom);
  /* Centra orizzontalmente rispetto all'ancora */
  left: anchor(center);
  translate: -50% 0;
}
```

**Fallback di posizionamento con `@position-try`:**

Quando il tooltip rischia di uscire dalla viewport, `@position-try` definisce posizioni alternative che il browser puo utilizzare automaticamente.

```css
.tooltip {
  position: fixed;
  position-anchor: --trigger;
  top: anchor(bottom);
  left: anchor(center);
  translate: -50% 8px;

  /* Se la posizione primaria non entra nella viewport,
     prova le alternative in ordine */
  position-try-fallbacks: --above, --left, --right;
}

@position-try --above {
  top: auto;
  bottom: anchor(top);
  translate: -50% -8px;
}

@position-try --left {
  top: anchor(center);
  left: auto;
  right: anchor(left);
  translate: -8px -50%;
}

@position-try --right {
  top: anchor(center);
  left: anchor(right);
  translate: 8px -50%;
}
```

**Ancoramento multiplo:**

Un elemento puo fare riferimento a piu ancore contemporaneamente, utile per connettori visivi, linee guida o elementi che si estendono tra due punti.

```css
.connector {
  position: fixed;
  top: anchor(--start-point bottom);
  bottom: anchor(--end-point top);
  left: anchor(--start-point center);
  right: anchor(--end-point center);
}
```

**Supporto browser e progressive enhancement:**

L'anchor positioning e supportato in Chrome 131+ e Edge 131+; Firefox e Safari hanno aggiunto il supporto nelle versioni piu recenti, ma l'adozione non e ancora uniforme come per altre funzionalita Baseline. Per i progetti in produzione, e consigliabile utilizzare `@supports (anchor-name: --test)` come feature detection e fornire un fallback basato su posizionamento tradizionale con `position: absolute` relativo a un contenitore con `position: relative`. Questa strategia di progressive enhancement garantisce che la funzionalita sia disponibile dove supportata, senza compromettere l'esperienza sugli altri browser. In alternativa, le librerie JavaScript leggere come Floating UI possono servire da polyfill funzionale fino a quando il supporto nativo non sara universale.

### @starting-style — Animazioni di Ingresso

La regola `@starting-style` definisce i valori iniziali delle proprieta di un elemento prima che le transizioni CSS entrino in azione. Questo risolve un problema storico: animare l'ingresso di elementi che passano da `display: none` a `display: block`, come dialog e popover.

**Problema risolto:**

Tradizionalmente, un elemento con `display: none` non partecipa alla cascata CSS e non puo essere il target di transizioni. Quando l'elemento diventa visibile (`display: block`), il browser lo renderizza immediatamente nel suo stato finale, senza possibilita di animare la transizione. `@starting-style` definisce esplicitamente lo stato "prima dell'ingresso", permettendo al browser di calcolare una transizione dall'inizio.

```css
dialog {
  opacity: 1;
  transform: translateY(0) scale(1);
  transition: opacity 0.3s ease-out,
              transform 0.3s ease-out,
              overlay 0.3s allow-discrete,
              display 0.3s allow-discrete;
}

/* Stato iniziale prima dell'apparizione */
@starting-style {
  dialog {
    opacity: 0;
    transform: translateY(-20px) scale(0.95);
  }
}

/* Stato di chiusura */
dialog:not([open]) {
  opacity: 0;
  transform: translateY(20px) scale(0.95);
}
```

**Transizioni per popover:**

```css
[popover] {
  opacity: 1;
  transform: scale(1);
  transition: opacity 0.2s ease,
              transform 0.2s ease,
              overlay 0.2s allow-discrete,
              display 0.2s allow-discrete;
}

@starting-style {
  [popover]:popover-open {
    opacity: 0;
    transform: scale(0.9);
  }
}

/* Stato di chiusura del popover */
[popover]:not(:popover-open) {
  opacity: 0;
  transform: scale(0.9);
}
```

La keyword `allow-discrete` nella transizione e necessaria per le proprieta discrete come `display` e `overlay`, che normalmente non sono animabili. Con `allow-discrete`, il browser mantiene il valore precedente durante la transizione e lo cambia solo alla fine.

### Popover Styling

L'API Popover nativa HTML/CSS, Baseline dal gennaio 2025, permette di creare tooltip, menu e overlay senza JavaScript per la logica di apertura/chiusura. Il CSS fornisce pseudo-classi e pseudo-elementi specifici per stilizzare i popover.

**`:popover-open` e `::backdrop`:**

```css
/* Stile del popover quando e aperto */
[popover]:popover-open {
  padding: 1.5rem;
  border: 1px solid var(--border-color);
  border-radius: var(--radius-lg);
  box-shadow: var(--shadow-lg);
  max-width: min(90vw, 400px);
}

/* Backdrop semi-trasparente */
[popover]::backdrop {
  background: oklch(0.15 0 0 / 0.5);
  backdrop-filter: blur(4px);
}
```

**Top layer:**

I popover vengono promossi nel top layer del browser, un contesto di impilamento speciale che si trova sopra tutti gli altri contenuti della pagina, inclusi gli elementi con `z-index` elevato. Questo elimina i problemi storici di z-index stacking per dropdown e modali. Il top layer e gestito dal browser e non puo essere manipolato direttamente tramite `z-index` o `position`.

**Combinazione con anchor positioning:**

La combinazione di popover nativi con anchor positioning crea un pattern completo per tooltip e dropdown senza dipendenze JavaScript per il posizionamento.

```css
.menu-trigger {
  anchor-name: --menu-trigger;
}

[popover].dropdown-menu {
  position: fixed;
  position-anchor: --menu-trigger;
  top: anchor(bottom);
  left: anchor(start);
  margin-top: 4px;

  &:popover-open {
    padding: 0.5rem 0;
    border-radius: var(--radius-md);
    box-shadow: var(--shadow-lg);
    min-width: 180px;
  }

  &::backdrop {
    background: transparent;
  }
}
```

### CSS Motion Path

Il CSS Motion Path Module permette di animare elementi lungo percorsi geometrici definiti, come curve di Bezier, archi, poligoni ed ellissi. Le proprieta principali sono `offset-path`, `offset-distance`, `offset-rotate` e `offset-anchor`.

**Animazione lungo un percorso SVG:**

```css
.moving-element {
  offset-path: path("M 0 200 Q 150 0 300 200 T 600 200");
  offset-distance: 0%;
  animation: follow-path 4s ease-in-out infinite alternate;
}

@keyframes follow-path {
  to { offset-distance: 100%; }
}
```

**Percorsi geometrici:**

```css
/* Percorso circolare */
.orbit {
  offset-path: circle(150px at center);
  offset-distance: 0%;
  animation: orbit 6s linear infinite;
}

@keyframes orbit {
  to { offset-distance: 100%; }
}

/* Percorso ellittico */
.elliptic-motion {
  offset-path: ellipse(200px 100px at center);
  offset-distance: 0%;
  offset-rotate: 0deg; /* Non ruota lungo il percorso */
  animation: elliptic 8s linear infinite;
}

@keyframes elliptic {
  to { offset-distance: 100%; }
}

/* Percorso poligonale */
.polygon-path {
  offset-path: polygon(0% 0%, 100% 0%, 100% 100%, 0% 100%);
  animation: move-polygon 5s linear infinite;
}

@keyframes move-polygon {
  to { offset-distance: 100%; }
}
```

**`offset-rotate` per orientamento automatico:**

La proprieta `offset-rotate` controlla l'orientamento dell'elemento lungo il percorso. Con il valore `auto`, l'elemento ruota automaticamente per seguire la tangente del percorso; con `auto 90deg`, aggiunge una rotazione fissa all'orientamento automatico; con un valore fisso come `0deg`, l'elemento mantiene un orientamento costante indipendentemente dalla curva.

```css
.vehicle {
  offset-path: path("M 0 300 C 100 100 200 500 300 300 S 500 100 600 300");
  offset-rotate: auto;
  animation: drive 5s ease-in-out infinite;
}

@keyframes drive {
  to { offset-distance: 100%; }
}
```

### Logical Properties

Le logical properties sostituiscono le proprieta fisiche (top, right, bottom, left, width, height) con equivalenti logici che si adattano automaticamente alla direzione di scrittura del testo. Questo le rende essenziali per siti web multilingue che supportano lingue RTL (right-to-left) come arabo, ebraico e persiano.

**Mappatura fisico-logico:**

| Fisico | Logico | Significato |
|---|---|---|
| `width` | `inline-size` | Dimensione lungo l'asse inline (orizzontale in LTR) |
| `height` | `block-size` | Dimensione lungo l'asse block (verticale in LTR) |
| `margin-top` | `margin-block-start` | Margine all'inizio dell'asse block |
| `margin-bottom` | `margin-block-end` | Margine alla fine dell'asse block |
| `margin-left` | `margin-inline-start` | Margine all'inizio dell'asse inline |
| `margin-right` | `margin-inline-end` | Margine alla fine dell'asse inline |
| `padding-left` | `padding-inline-start` | Padding all'inizio dell'asse inline |
| `padding-right` | `padding-inline-end` | Padding alla fine dell'asse inline |
| `border-top` | `border-block-start` | Bordo all'inizio dell'asse block |
| `border-left` | `border-inline-start` | Bordo all'inizio dell'asse inline |
| `top` | `inset-block-start` | Offset dall'inizio dell'asse block |
| `left` | `inset-inline-start` | Offset dall'inizio dell'asse inline |
| `text-align: left` | `text-align: start` | Allineamento all'inizio della direzione inline |

**Shorthand logici:**

```css
.component {
  /* Padding su asse inline (sinistro+destro in LTR) */
  padding-inline: 1rem 2rem; /* start end */

  /* Padding su asse block (superiore+inferiore in LTR) */
  padding-block: 1.5rem;     /* uguale per start e end */

  /* Margini logici */
  margin-inline: auto;       /* Centratura orizzontale (funziona anche in RTL) */
  margin-block: 2rem 0;

  /* Dimensioni logiche */
  inline-size: 100%;
  max-inline-size: 65ch;
  min-block-size: 100dvh;

  /* Bordi logici */
  border-inline-start: 4px solid var(--color-accent);

  /* Inset logico (equivalente di top/right/bottom/left) */
  inset-block: 0;
  inset-inline: 0;
}
```

**`border-radius` logico:**

Anche il border-radius ha i suoi equivalenti logici, fondamentali per garantire che gli angoli arrotondati siano coerenti con la direzione del testo.

```css
.card {
  /* Fisico: border-radius: top-left top-right bottom-right bottom-left */
  /* Logico: */
  border-start-start-radius: var(--radius-lg); /* block-start + inline-start */
  border-start-end-radius: var(--radius-lg);   /* block-start + inline-end */
  border-end-start-radius: 0;                  /* block-end + inline-start */
  border-end-end-radius: 0;                    /* block-end + inline-end */
}
```

**Quando usare le logical properties:**

Per i progetti internazionali o le librerie di componenti destinate a un uso globale, le logical properties dovrebbero essere il default. Per progetti monolingua in lingue LTR, l'adozione e comunque consigliata per future-proofing e coerenza, anche se l'impatto pratico immediato e limitato.

### Funzioni Matematiche CSS

CSS dispone oggi di un set completo di funzioni matematiche che riducono la dipendenza da preprocessori e JavaScript per i calcoli.

**`min()`, `max()` e `clamp()` — approfondimento:**

Queste tre funzioni sono il pilastro della tipografia e delle spaziature fluide. `min()` seleziona il valore piu piccolo tra i suoi argomenti, `max()` il piu grande, e `clamp()` vincola un valore tra un minimo e un massimo.

```css
.container {
  /* min(): non superare mai il 90% del viewport o 1200px */
  width: min(90vw, 1200px);

  /* max(): almeno 300px, ma puo crescere fino al 50% del viewport */
  min-width: max(300px, 50vw);

  /* clamp(): valore fluido con vincoli */
  padding: clamp(1rem, 3vw, 3rem);
}

/* Tipografia fluida con clamp */
h1 { font-size: clamp(2rem, 1rem + 4vw, 4.5rem); }
h2 { font-size: clamp(1.5rem, 0.8rem + 3vw, 3rem); }
h3 { font-size: clamp(1.25rem, 0.7rem + 2vw, 2rem); }
```

**`round()`, `mod()` e `rem()`:**

Le funzioni `round()`, `mod()` e `rem()` portano operazioni aritmetiche avanzate nel CSS, utili per allineamenti a griglia, pattern ripetitivi e calcoli di spaziatura.

```css
/* round(): arrotonda un valore a un multiplo specificato */
.element {
  /* Arrotonda la larghezza al multiplo di 50px piu vicino */
  width: round(nearest, 33vw, 50px);

  /* Arrotonda per eccesso */
  height: round(up, 45%, 10%);

  /* Arrotonda per difetto */
  font-size: round(down, 2.7rem, 0.25rem);
}

/* mod(): restituisce il resto della divisione (segno del divisore) */
.grid-item {
  /* Utile per pattern alternati senza nth-child */
  margin-left: mod(100px, 30px); /* = 10px */
}

/* rem(): resto della divisione (segno del dividendo) */
.pattern {
  offset-distance: rem(var(--position), 100%);
}
```

**`abs()` e `sign()`:**

```css
/* abs(): valore assoluto */
.element {
  /* Garantisce sempre un valore positivo */
  margin-top: abs(var(--offset));
}

/* sign(): restituisce -1, 0 o 1 in base al segno */
.directional {
  /* Applicare una trasformazione nella direzione del valore */
  transform: translateX(calc(sign(var(--direction)) * 100px));
}
```

**`calc()` avanzato con annidamento:**

```css
.complex-layout {
  /* Calcoli annidati per layout complessi */
  width: calc(100% - calc(var(--sidebar-width) + var(--gap) * 2));

  /* Combinazione con min/max/clamp */
  padding: calc(clamp(1rem, 3vw, 3rem) * 0.5);

  /* Calcoli con unita miste */
  height: calc(100vh - var(--header-height) - var(--footer-height));
}
```

### content-visibility e Performance di Rendering

La proprieta `content-visibility` e una delle ottimizzazioni di rendering piu efficaci introdotte nel CSS. Con il valore `auto`, il browser salta il rendering (layout, paint) degli elementi fuori dalla viewport, riducendo drasticamente i tempi di caricamento iniziale. Test documentati mostrano riduzioni del tempo di rendering fino al 7x su pagine con contenuti lunghi.

**Utilizzo base:**

```css
/* Applica content-visibility alle sezioni sotto il fold */
.below-fold-section {
  content-visibility: auto;
  contain-intrinsic-size: auto 500px;
}

article + article {
  content-visibility: auto;
  contain-intrinsic-size: auto 300px;
}
```

**`contain-intrinsic-size`:**

La proprieta `contain-intrinsic-size` definisce una dimensione placeholder per gli elementi il cui contenuto non e ancora stato renderizzato. Senza questa proprieta, gli elementi con `content-visibility: auto` hanno dimensione zero quando non sono visibili, causando jump della scrollbar e problemi di CLS (Cumulative Layout Shift). Il valore `auto` combinato con una dimensione (es. `auto 500px`) permette al browser di ricordare la dimensione reale dopo il primo rendering e utilizzarla come placeholder nelle visite successive.

```css
.article-card {
  content-visibility: auto;
  /* Il browser usa 400px come stima iniziale, poi memorizza la dimensione reale */
  contain-intrinsic-size: auto 400px;
}
```

**Quando usare e quando evitare:**

Usare `content-visibility: auto` per: sezioni di contenuto lungo sotto il fold, liste con molti elementi, articoli di blog, feed infiniti, tabelle con centinaia di righe. Evitare per: contenuti above-the-fold (ritarda il rendering iniziale), elementi con dimensioni molto variabili (problemi di CLS), sezioni che contengono script critici che devono eseguire immediatamente.

**Interazione con `contain` e le altre proprieta di containment:**

La proprieta `content-visibility: auto` attiva implicitamente layout containment, style containment e paint containment sull'elemento. Questo significa che l'elemento diventa un containing block per i discendenti posizionati in modo assoluto, impedisce ai contatori e alle quote di influenzare gli antenati, e impedisce al rendering dei contenuti di fuoriuscire dai limiti dell'elemento. Queste implicazioni di containment possono occasionalmente causare effetti collaterali inaspettati, come la rottura di layout che dipendono dal overflow visibile o da contatori CSS che attraversano i limiti del componente. E quindi fondamentale testare il comportamento dopo l'applicazione di `content-visibility` per verificare che nessuna funzionalita dipendente dal flusso normale del documento venga compromessa.

**`content-visibility: hidden` vs `display: none`:**

A differenza di `display: none`, che rimuove l'elemento dal rendering tree, `content-visibility: hidden` mantiene lo stato dell'elemento (layout calcolato, stato dei form, posizione dello scroll) ma ne nasconde il contenuto. Questo e ideale per tab panels e pannelli accordion dove il contenuto deve essere pre-renderizzato ma nascosto.

```css
/* Tab panel: mantiene lo stato ma nasconde il contenuto */
.tab-panel:not(.active) {
  content-visibility: hidden;
}

/* Piu efficiente di display: none per contenuti che cambiano frequentemente */
```

### View Transitions API — Approfondimento

Oltre alla sintassi base gia trattata nella sezione sulle animazioni, la View Transitions API merita un approfondimento sulle transizioni tra pagine (cross-document) e sulla personalizzazione avanzata delle animazioni.

**Transizioni cross-document (MPA):**

Per le applicazioni multi-pagina (MPA), le view transitions funzionano senza JavaScript: basta aggiungere una regola CSS `@view-transition` e assegnare `view-transition-name` agli elementi che devono animarsi tra le pagine.

```css
/* Abilita le view transitions tra pagine dello stesso origin */
@view-transition {
  navigation: auto;
}

/* Assegna nomi di transizione agli elementi persistenti */
.site-header {
  view-transition-name: header;
}

.hero-image {
  view-transition-name: hero;
}

.main-content {
  view-transition-name: content;
}

/* Personalizza le animazioni per elemento */
::view-transition-old(hero) {
  animation: scale-down-fade 0.4s ease-in forwards;
}

::view-transition-new(hero) {
  animation: scale-up-fade 0.4s ease-out;
}

@keyframes scale-down-fade {
  to {
    transform: scale(0.9);
    opacity: 0;
  }
}

@keyframes scale-up-fade {
  from {
    transform: scale(0.9);
    opacity: 0;
  }
}
```

**View transition classes e types:**

I view transition types permettono di applicare animazioni diverse a seconda della direzione della navigazione (avanti, indietro, verso una sotto-pagina).

```css
/* Transizione verso destra (navigazione avanti) */
::view-transition-old(content):is(.forward *) {
  animation: slide-out-left 0.3s ease-in;
}

::view-transition-new(content):is(.forward *) {
  animation: slide-in-right 0.3s ease-out;
}

/* Transizione verso sinistra (navigazione indietro) */
::view-transition-old(content):is(.back *) {
  animation: slide-out-right 0.3s ease-in;
}

::view-transition-new(content):is(.back *) {
  animation: slide-in-left 0.3s ease-out;
}

@keyframes slide-out-left {
  to { transform: translateX(-100%); opacity: 0; }
}

@keyframes slide-in-right {
  from { transform: translateX(100%); opacity: 0; }
}
```

### CSS Modules vs CSS-in-JS — Confronto

La scelta tra CSS Modules e CSS-in-JS e una delle decisioni architetturali piu dibattute nello sviluppo frontend moderno. Entrambi risolvono il problema dello scoping degli stili, ma con approcci e compromessi molto diversi.

**CSS Modules:**

I CSS Modules trasformano i nomi delle classi in identificatori unici a build-time, garantendo l'isolamento senza runtime overhead. Il CSS risultante e un normale file CSS statico, ottimizzabile e cacheable dal browser.

```css
/* Button.module.css */
.button {
  padding: 0.5rem 1rem;
  border-radius: 4px;
  cursor: pointer;
}

.primary {
  background: var(--color-action);
  color: white;
}

/* Compilato in: .Button_button_x7k2a { ... } .Button_primary_h3j1b { ... } */
```

**CSS-in-JS (styled-components, Emotion):**

Le librerie CSS-in-JS generano gli stili a runtime nel browser, iniettando tag `<style>` nel DOM. Offrono composizione dinamica potente, ma con costo di performance a runtime.

**Tabella comparativa:**

| Criterio | CSS Modules | CSS-in-JS | CSS Nativo (@scope + @layer) |
|---|---|---|---|
| Scoping | Hash a build-time | Runtime injection | Prossimita nativa |
| Performance | Zero runtime cost | Runtime parsing e injection | Zero runtime cost |
| Bundle size | CSS separato, cacheable | JS bundle piu pesante | CSS separato, cacheable |
| Dynamic styling | Limitato (classi condizionali) | Pieno (props, stato, theme) | Custom properties + `:has()` |
| Server-Side Rendering | Nativo, zero FOUC | Richiede estrazione CSS | Nativo, zero FOUC |
| DX (Developer Experience) | Buona, tipi con TypeScript plugin | Eccellente, co-locazione | Buona, standard nativo |
| Tooling richiesto | Bundler (Webpack, Vite) | Nessuno (runtime) o bundler | Nessuno |
| Debugging DevTools | Nomi hash (leggibilita ridotta) | Nomi hash o generati | Nomi originali |

**Quando scegliere cosa:**

CSS Modules sono la scelta consigliata per la maggior parte dei progetti: zero overhead a runtime, compatibilita universale con i bundler moderni, e output CSS standard cacheable. CSS-in-JS e giustificato quando il progetto ha esigenze forti di theming dinamico basato su props o stato React, ma il costo di performance deve essere misurato e accettato consapevolmente. La combinazione di `@scope`, `@layer` e custom properties nel CSS nativo sta emergendo come alternativa che non richiede alcun tooling aggiuntivo, sebbene `@scope` sia ancora relativamente recente per progetti con requisiti di compatibilita stringenti.

**Impatto sulle performance di rendering:**

CSS Modules e CSS nativo producono fogli di stile statici che il browser puo parsificare una volta sola e cachare efficacemente. Le soluzioni CSS-in-JS a runtime (come styled-components senza il plugin Babel per l'estrazione) devono serializzare gli stili in stringhe, parsificarli e iniettarli nel DOM ad ogni render del componente React, con un impatto misurabile sul Time to Interactive (TTI) e sull'Interaction to Next Paint (INP). Progetti ad alte performance come e-commerce, landing page e applicazioni con rendering frequente dovrebbero preferire CSS Modules o CSS nativo. Librerie CSS-in-JS con estrazione a build-time come Vanilla Extract o Linaria offrono un compromesso ragionevole: la DX del CSS-in-JS con le performance del CSS statico, poiche generano file CSS a compile-time anziche a runtime.

**Evoluzione dell'ecosistema:**

La tendenza dell'ecosistema frontend nel 2024-2025 mostra un chiaro spostamento verso soluzioni zero-runtime. Framework come Next.js hanno rimosso il supporto per styled-components nel Server Component model, e la community React sta convergendo verso CSS Modules, Tailwind CSS o soluzioni a build-time. Le nuove funzionalita CSS native (`@scope`, `@layer`, `:has()`, custom properties avanzate) stanno riducendo progressivamente i casi d'uso che giustificavano l'adozione di CSS-in-JS, poiche molte delle funzionalita che richiedevano JavaScript (scoping, theming condizionale, stili basati sullo stato) sono ora realizzabili in puro CSS.

## Esercizi

### Esercizio 1 — Layout responsive con Flexbox e Grid

**Obiettivo:** Costruire un layout di pagina completo usando esclusivamente Flexbox e CSS Grid, senza framework.

- Creare una pagina con header (logo + nav), area contenuto principale a 3 colonne su desktop (sidebar, main, aside), e footer
- Il layout deve passare a colonna singola sotto i 768px (mobile-first con `min-width` media query)
- Utilizzare CSS Grid per la struttura generale della pagina (`grid-template-areas`) e Flexbox per la distribuzione degli elementi nella navbar e nel footer
- Applicare `gap` per la spaziatura tra gli elementi (nessun margin hack)
- Le colonne laterali devono avere larghezza fissa su desktop e scomparire su mobile
- Verificare che non ci siano overflow orizzontali a nessuna viewport tra 320px e 1920px

### Esercizio 2 — Sistema di design token con custom properties

**Obiettivo:** Implementare un sistema completo di design token usando CSS custom properties con supporto dark mode.

- Definire token primitivi su `:root`: palette colori (almeno 5 livelli per colore primario e neutro), scale tipografiche con `clamp()`, scale di spaziatura (4px base), border-radius e shadow
- Creare token semantici che referenziano i primitivi: `--color-surface`, `--color-text-primary`, `--color-text-secondary`, `--color-accent`, `--color-error`
- Implementare il dark mode con `@media (prefers-color-scheme: dark)` che sovrascrive solo i token semantici
- Applicare i token a una card component (titolo, testo, immagine, bottone) con stati hover e focus
- Aggiungere un toggle manuale dark/light con `:has()` e un checkbox nascosto che sovrascrive il tema di sistema
- Verificare il contrasto WCAG AA (4.5:1 per testo normale) in entrambi i temi

### Esercizio 3 — Animazioni compositor-friendly e transizioni

**Obiettivo:** Creare una serie di animazioni performanti che utilizzano solo proprieta compositor-friendly.

- Implementare una hero section con testo che appare con `@keyframes` animando `opacity` e `transform: translateY()`
- Creare un bottone con transizione multi-proprieta su hover: `transform: scale()`, `box-shadow` e `background-color` con easing personalizzati (`cubic-bezier`)
- Aggiungere una card con effetto flip 3D al hover usando `transform: rotateY()`, `perspective` e `backface-visibility`
- Implementare una loading spinner con `@keyframes` e `animation` senza JavaScript
- Racchiudere tutte le animazioni in `@media (prefers-reduced-motion: no-preference)` con un fallback statico per utenti che richiedono riduzione del movimento
- Misurare con Chrome DevTools (tab Performance) che nessuna animazione causi reflow o repaint

### Esercizio 4 — Container queries e CSS nesting

**Obiettivo:** Costruire componenti che si adattano in base al contenitore padre usando container queries e CSS nesting nativo.

- Creare un componente card con `container-type: inline-size` sul wrapper
- La card deve mostrare layout verticale (immagine sopra, testo sotto) quando il contenitore e stretto (<400px) e layout orizzontale (immagine a sinistra, testo a destra) quando e largo (>=400px)
- Utilizzare `@container` queries per le variazioni di layout, non media queries
- Riscrivere tutto il CSS del componente usando CSS nesting nativo (senza preprocessori): selettori annidati, `&` per riferimento al parent, media query annidate
- Inserire la stessa card in 3 contesti diversi (sidebar stretta, main content, full-width) per dimostrare che si adatta automaticamente
- Applicare `@layer` per organizzare gli stili in reset, base, components, utilities

### Esercizio 5 — Pagina editoriale con tipografia avanzata e grid complessa

**Obiettivo:** Realizzare un layout editoriale (stile magazine) che dimostri padronanza di Grid avanzato e tipografia responsive.

- Creare un layout a griglia asimmetrica con `grid-template-columns: repeat(12, 1fr)` dove gli articoli occupano span diversi (es. hero 12 colonne, featured 8+4, standard 4+4+4)
- Implementare tipografia responsive con `clamp()` per tutti i livelli di heading (h1-h4) e body text
- Utilizzare `::first-letter` con stile drop-cap sull'articolo principale
- Aggiungere immagini che si estendono fuori dalla griglia con `grid-column: 1 / -1` per effetto full-bleed
- Implementare `scroll-snap-type: y mandatory` per le sezioni a tutta altezza con `scroll-snap-align: start`
- Applicare `text-wrap: balance` sui titoli e `text-wrap: pretty` sui paragrafi dove supportato
- Verificare che il layout funzioni correttamente da 320px a 1920px senza media query eccessive (massimo 3 breakpoint)

### Esercizio 6 — Scroll-driven animations e View Transitions

**Obiettivo:** Implementare animazioni legate allo scroll e transizioni tra viste usando esclusivamente CSS moderno, senza librerie JavaScript.

- Creare una barra di progresso di lettura fissa in cima alla pagina che si riempie da sinistra a destra durante lo scroll, usando `animation-timeline: scroll(root)` con un keyframe che anima `transform: scaleX()` da 0 a 1. La barra deve utilizzare `transform-origin: left` per l'ancoraggio corretto
- Implementare almeno 6 sezioni di contenuto con animazioni di reveal: ogni sezione deve apparire con un effetto `fade-in-up` (opacita da 0 a 1 e traslazione verticale di 50px) legato al `view()` timeline, con `animation-range: entry 0% entry 100%`
- Aggiungere un effetto parallax su un'immagine hero usando `animation-timeline: scroll()` dove l'immagine si muove verticalmente a velocita diversa rispetto allo scroll (translateY da -15% a 15%)
- Configurare View Transitions tra almeno due pagine dello stesso dominio usando `@view-transition { navigation: auto; }` con `view-transition-name` assegnato a header, main content e un'immagine condivisa. Personalizzare le animazioni con `::view-transition-old` e `::view-transition-new` usando transizioni di scala e opacita
- Racchiudere tutte le animazioni scroll-driven in `@media (prefers-reduced-motion: no-preference)` e verificare che la pagina sia completamente funzionale senza animazioni quando la preferenza di riduzione del movimento e attiva
- Misurare con Chrome DevTools che le animazioni non blocchino il main thread

### Esercizio 7 — CSS avanzato: @property, anchor positioning e @scope

**Obiettivo:** Costruire un'interfaccia interattiva che dimostri padronanza delle funzionalita CSS piu recenti: `@property` per animazioni di gradienti, anchor positioning per tooltip nativi e `@scope` per isolamento degli stili.

- Registrare almeno 3 custom properties con `@property`: un angolo per la rotazione di un gradiente conico, un colore per una transizione di sfondo e un numero per un contatore animato. Animare tutte e tre con `transition` e `@keyframes`, dimostrando che le transizioni funzionano solo dopo la registrazione
- Creare un sistema di tooltip completamente CSS usando anchor positioning: definire 4 trigger con `anchor-name`, ciascun tooltip con `position-anchor` e posizionamento tramite `anchor(bottom)` e `anchor(center)`. Implementare `@position-try` con almeno 3 posizioni di fallback (sopra, sinistra, destra) per gestire i casi in cui il tooltip fuoriesce dalla viewport
- Implementare `@starting-style` per animare l'apertura di un elemento `<dialog>`: lo stato iniziale deve avere `opacity: 0` e `transform: translateY(-20px) scale(0.95)`, con transizione fluida allo stato finale. Aggiungere anche `::backdrop` con sfocatura progressiva
- Utilizzare `@scope` per creare due varianti di un componente card (`.light-card` e `.dark-card`) dove gli stili interni (titoli, paragrafi, link) sono scoped al componente. Implementare un donut scope con `@scope (.card) to (.card__slot)` che protegga il contenuto dello slot dal ricevere gli stili della card
- Definire tutte le dimensioni con logical properties (`inline-size`, `padding-block`, `margin-inline`) e verificare che il layout funzioni correttamente in modalita `direction: rtl`
- Utilizzare `color-mix(in oklch, ...)` e la sintassi dei colori relativi per derivare l'intera palette colori da un singolo colore base custom property

## Glossario

| Termine | Definizione |
|---|---|
| **Box model** | Modello che descrive ogni elemento come un rettangolo composto da content, padding, border e margin. |
| **Flexbox** | Modulo di layout CSS per la distribuzione degli elementi su un singolo asse (riga o colonna). |
| **CSS Grid** | Modulo di layout CSS bidimensionale che organizza gli elementi in righe e colonne simultaneamente. |
| **Custom property** | Variabile CSS dichiarata con `--nome` e letta con `var(--nome)`, disponibile a runtime e ereditata nella cascata. |
| **Container query** | Regola `@container` che applica stili in base alle dimensioni del contenitore padre, non della viewport. |
| **CSS nesting** | Sintassi nativa che consente di annidare selettori all'interno di una regola CSS, riducendo la ripetizione. |
| **Cascade layer** | Livello dichiarato con `@layer` che controlla la priorita degli stili indipendentemente dalla specificita dei selettori. |
| **Media query** | Regola `@media` che applica stili condizionali in base a caratteristiche del dispositivo (larghezza, preferenze utente, ecc.). |
| **Specificita** | Algoritmo che determina quale regola CSS prevale quando piu regole si applicano allo stesso elemento. |
| **Compositor thread** | Thread del browser che gestisce le animazioni di `transform` e `opacity` senza coinvolgere il main thread. |
| **Reflow** | Ricalcolo delle posizioni e dimensioni degli elementi nel layout, operazione costosa innescata da proprieta come `width` o `margin`. |
| **Repaint** | Ridisegno dei pixel sullo schermo senza ricalcolo del layout, innescato da proprieta come `color` o `background-color`. |
| **BEM** | Block-Element-Modifier: convenzione di nomenclatura CSS che struttura le classi come `.block__element--modifier`. |
| **Logical properties** | Proprieta CSS (`inline-size`, `block-start`, ecc.) che si adattano automaticamente alla direzione di scrittura (LTR/RTL). |
| **`clamp()`** | Funzione CSS che definisce un valore fluido con minimo, preferito e massimo: `clamp(min, preferred, max)`. |
| **`@scope`** | Regola CSS che limita l'applicabilita degli stili a un sottoalbero del DOM, con supporto per donut scope e scoping di prossimita. |
| **`@property`** | Regola che registra formalmente una custom property specificando tipo, valore iniziale e comportamento di ereditarieta, abilitandone l'animazione. |
| **OKLCH** | Spazio colore percettivamente uniforme (Oklab Lightness Chroma Hue) che garantisce variazioni di luminosita coerenti indipendentemente dalla tonalita. |
| **`color-mix()`** | Funzione CSS che mescola due colori in uno spazio colore specificato con proporzioni personalizzabili. |
| **Relative color syntax** | Sintassi che permette di derivare un nuovo colore da uno esistente modificando selettivamente i singoli canali (es. `oklch(from var(--base) calc(l + 0.1) c h)`). |
| **Scroll-driven animations** | Animazioni CSS legate alla posizione di scorrimento anziche al tempo, tramite `animation-timeline: scroll()` o `view()`. |
| **View timeline** | Timeline di animazione legata alla visibilita di un elemento all'interno del suo scroll container. |
| **Anchor positioning** | Meccanismo CSS che posiziona un elemento in relazione a un altro (l'ancora) ovunque nella pagina tramite `anchor-name` e `position-anchor`. |
| **`@starting-style`** | Regola che definisce i valori iniziali delle proprieta prima delle transizioni, risolvendo l'animazione di ingresso per elementi con `display: none`. |
| **Top layer** | Contesto di impilamento speciale del browser che ospita popover e dialog, posizionato sopra tutti gli altri contenuti della pagina. |
| **Motion path** | Modulo CSS che permette di animare elementi lungo percorsi geometrici definiti tramite `offset-path`, `offset-distance` e `offset-rotate`. |
| **`content-visibility`** | Proprieta che istruisce il browser a saltare il rendering degli elementi fuori viewport, migliorando drasticamente le performance di caricamento. |
| **`contain-intrinsic-size`** | Proprieta che definisce una dimensione placeholder per elementi con `content-visibility: auto`, prevenendo jump della scrollbar. |
| **Style queries** | Estensione delle container queries che permette di interrogare il valore delle custom properties del container, non solo le dimensioni. |
| **CSS Modules** | Tecnica che trasforma i nomi delle classi CSS in identificatori unici a build-time, garantendo isolamento degli stili senza overhead a runtime. |
| **View Transitions API** | API CSS/JS che crea transizioni animate tra stati della pagina o tra pagine diverse, catturando snapshot del DOM prima e dopo il cambiamento. |
| **Donut scope** | Pattern `@scope` che definisce un limite inferiore oltre il quale le regole non si applicano, proteggendo i componenti annidati. |
